# 最终备货建议

## 业务用途

把同一 Amazon 店铺本轮的销量、FBA 库存、本地商品编码和未发出货件整理为可供运营判断空运、海运及备货数量的最终 Excel。结果是单工作表 `mskulist`、A:AI 共 35 列；趋势、日均销量、R“FBA总库存”及建议沿用原 13 列公式，另在 AI 增加“可供天数”，共 14 个公式字段。AG“本地库存”来自 MSKU `uq122`，T“未发出货件总计”来自货件快照，其他源数据按既有映射保留。

这是独立最终表流程，普通备货的参数方案和原有报表仍由 `replenishment-workflow-map` / `replenishment-calculate` 负责。表头、样式和公式由代码生成，运营无需上传模板。

## 入口与范围

- Amazon 业务已明确且用户明确要求“最终备货建议”时使用本 Skill，先解析用户提供的店铺名，身份确认后执行本轮取数；不限定店铺或关键词组合，不要求额外出现中文“亚马逊”，不因其他店铺而重复确认备货类型。明确普通备货走 `replenishment-workflow-map` / `replenishment-calculate`；仅要求发送旧流程的最终文件，不代表切换到本 Skill。
- 明确其他 ERP 或东南亚请求不使用本 Skill，沿用对应业务 Skill 或 `southeast-asia-replenishment-workflow-map`，不因“最终备货建议”字样切到 Amazon。只有平台业务真正不明确时才澄清；能从本轮上下文判断为 Amazon 时不重复询问平台，也不凭国家或简称猜来源。
- 只有备货类型不明确时才选择“普通备货”或“最终备货建议”，如只说“亚马逊备货建议”且上下文未确定类型，或提出相互冲突的流程要求。使用现有 `ask_user_question` 提问“本次使用哪种备货流程？”，单选项为“普通备货”（原有算法和报表）与“最终备货建议”（本轮自动取数，生成独立 35 列 Excel）；没有该工具时用对话列出相同选项并等待。未选择前不执行店铺解析、取数或计算；跳过、取消或未明确选择时停止生成，不默认任一选项。
- 已明确或已选择的备货类型沿用，不重复提问。选择普通流程后读取 `replenishment-workflow-map`；选择最终流程后继续本 Skill，不要求补齐关键词。更换店铺但未更改备货类型时，只核对新店铺，不重新选择流程。
- 仅询问流程、规则或已有结果时解释或读取对应产物，不重新生成。明确的单步取数请求交给对应业务 Skill，不要求选择整套流程。入口确认后，用户只需提供店铺名，默认在本轮自动取数，不向用户索取三个文件路径；也不转入旧备货计算。
- 本 Skill 的正常对外生成只需店铺名，并在本轮自动取数、核验、计算和交付；允许用户在当前请求明确指定旺季加成及天数，无需补充文件。用户只提供文件或要求离线文件计算时，说明此入口需要店铺名以启动自动流程；不要求用户补交三份文件，也不把用户文件或历史文件混入本轮输入。
- 不搜索历史目录或自行按修改时间挑选文件，不猜店铺别名、网页 ID、批次或文件路径。店铺名称不明确时交给现有解析能力，解析有歧义时只展示真实候选，不自动选第一个；缺少店铺名且上下文无法确定时只补问店铺名。店铺歧义不改变已明确的备货类型。

| 生成这家店的最终备货建议。 | 上下文无法确定平台时，只澄清平台业务，保留已明确的最终备货意图。 |

## 仅给店铺名时的本轮取数

按下表顺序读取对应业务 Skill，通过 `exec` 调用其已声明的 CLI；需要确认命令或参数时，使用 `lxeskill list` 和 `lxeskill describe <业务命令路径>` 查询公开契约，不直接读取 CLI 内部目录文件。`internal` 命令默认不出现在 `list` 中；桌面设置命令不属于本 Skill 的模型业务入口。这里只说明本流程需要的输入及交接字段，不额外维护可选参数。

| 顺序与能力 | 业务用途、何时调用及输入 | 返回结果与下一步 |
|---|---|---|
| 1 店铺解析：`replenishment-store-resolve` / `lxeskill replenish store resolve --store-name "<用户店铺名>"` | 入口确认后，把运营名称解析成马帮下载入口的真实店铺和查询标识；不是紫鸟店铺 ID。 | `data.store_name`、`store_id`、`id_type` 传给步骤 2。歧义时展示真实候选；整组须选择单站点，不猜 ID 或自动拆任务。 |
| 2 MSKU 源表：`mabang-store-msku-export` / `lxeskill mabang store msku export --store-id "<store_id>" --id-type "<id_type>" --store-name "<规范店铺名>" --include-local-inventory` | 按步骤 1 的标识下载本轮商品行、销量、FBA 库存和重量，启用本地库存列；导出同时保存既有本地 SKU 商品类型核验结果。 | `data.xlsx_path`、`store_name` 及原始/核验通过/未通过行数。源表供步骤 3 查深圳库存，供步骤 5 取基础数据和 AG；缺本地库存列或接口失败停止，不用深圳数量替代。 |
| 3 深圳库存报告：`mabang-store-shenzhen-inventory-export` / `lxeskill mabang store shenzhen-inventory export --store-name "<规范店铺名>" --msku-source-xlsx-path "<步骤2返回的xlsx_path>"` | 源表成功后，显式传入本轮路径，按既有能力完整导出深圳报告。本流程用报告核对来源、报表MSKU身份和商品编码；“无本地SKU”“无库存数据”的合法占位行不因此阻断，不把占位0当作真实库存，也不写入AG。AG只取源表uq122；报告缺失、损坏或来源异常仍停止。 | `data.shenzhen_warehouse_inventory_report_xlsx_path`、`source_msku_xlsx_path`、`source_msku_data_time`。先核对同源，再进入步骤 4；报告供步骤 5 校验及填 AH，不作为 AG 来源。 |
| 4 货件快照：`mabang-store-unlinked-shipments-export` / `lxeskill mabang store unlinked-shipments export --store-name "<规范店铺名>"` | 同源检查通过后，查询 WMS待配货、WMS待装箱、待关联货件三个状态，自动下载原生文件并按 MSKU 汇总商品件数，作为 T 的现有统计输入。 | `data.status_results` 及 `data.snapshot.snapshot_xlsx_path`、布尔值 `confirmed_empty`。快照供步骤 5 填 T；发货单张数不等于商品件数。状态缺失或快照失败停止。 |
| 5 最终计算：本 Skill / `lxeskill replenish final-restock generate` | 三份本轮产物齐全后，传规范店铺名和它们的路径；校验店铺、来源批次、覆盖及数值，生成 Excel，经 Office Kit 重算并检查。 | `data.output_xlsx_path`、`source_data_time`、`row_count`、`formula_error_count` / `formula_error_examples`；仅合法成功结果交给步骤 6，错误结果按诊断处理。 |
| 6 文件交付：`send_files` | 计算检查通过后，使用最终 terminal 的 `files`，不发中间报表，不自行猜路径。 | 发送工具确认成功才算交付；失败只重试交付，不重新取数或生成。 |

- 步骤 2 返回的店铺名须与规范店铺名一致。步骤 3 必须通过 `--msku-source-xlsx-path` 使用步骤 2 本轮返回的 `xlsx_path`；指定文件不存在、损坏或核验不通过时停止，不回退历史文件或省略参数重试。**在调用步骤 4 之前**仍核对：步骤 3 的 `source_msku_xlsx_path` 必须指向步骤 2 本轮返回的 `xlsx_path`；不一致就结束本轮，不得继续取货件或调用最终计算。底层计算仍会核验文件指纹、店铺、批次、快照及 MSKU 覆盖。
- 步骤 4 只有三个状态完整成功且快照存在才可继续；`confirmed_empty=true` 是有效空快照，查询失败或缺快照不能当作零货件。不要再运行旧销量分析或 `replenish calculate`。

## 输入与调用

步骤 5 的四项参数依次来自步骤 1 的规范店铺、步骤 2/3/4 的产物路径。只使用本轮成功返回的路径，属于 Agent 内部计算接口，不构成运营上传三文件的入口。通过 `exec` 执行一次独立命令，不拼接 shell 操作、不直接执行 Python 业务模块：

```text
lxeskill replenish final-restock generate --store-name "<完整店铺名>" --msku-source-xlsx-path "<源文件路径>" --shenzhen-inventory-report-xlsx-path "<深圳报告路径>" --unlinked-shipments-snapshot-path "<货件快照路径>"
```

## 三份数据的职责

| 输入 | 在最终表中的职责 | 不能混用的口径 |
|---|---|---|
| MSKU 源表 | 商品行、销量、FBA 库存、重量等基础数据；AG“本地库存”读取步骤 2 源表中每个 MSKU 自身的“本地库存”，对应导出字段 `uq122`，包括组合 MSKU。 | AG唯一数值来源为uq122；正数、真实0、有限负数及合法数字文本均允许。逐MSKU校验，缺失、空白、非法或非有限则停止整张正式表并报告具体MSKU与原因；不改用深圳库存或占位0。 |
| 深圳库存报告 | 同源批次、全量报告MSKU身份及商品编码核对；AH“本地SKU”优先取报告的本地SKU列（普通商品或组合商品编码），为空时回退源表本地SKU。 | 报告非空编码优先，允许与源表不同；不填子SKU拆分文本。编码优先级不取消店铺、批次、指纹、报表结构和MSKU身份完整性核验；不要求100%存在深圳真实库存记录，合法占位保留。组合组件由既有核验/库存导出处理，最终计算不新增第二套绑定规则；深圳数量不参与本表建议公式，也不替代 AG。 |
| 未关联货件快照 | T“未发出货件总计”按店铺和 MSKU 读取快照商品数量，参与现有建议计算；须与源表同店、同日。 | 使用快照件数而非发货单张数；不由 Agent 再扣一次。完整有效快照中没有该 MSKU 时为 0，查询失败不能当 0。 |

T 的状态覆盖及与 FBA 在途是否重叠尚待业务验收，不能据此宣称已消除重复扣减或重复备货；沿用现有统计与公式，不由 Agent 调整数量或补做去重。

- “绑定核验”沿用既有返回字段，实际表示商品类型已确认，不证明实时 Listing 绑定一致；不额外查询 Listing。A口径保留全部 MSKU 及核验结果，绑定核验未通过也写入原 13 列公式和 AI，共 14 个公式字段；U–AC 可产生建议。商品类型核验失败不等于没有库存，也不能用报告行数证明有真实库存；深圳库存记录缺失不等于AG缺失；AG必需值按uq122独立校验。源表核验标签中的旧“不参与备货计算”说明不作为本最终流程的计算资格开关，普通备货仍沿用原契约。
- 旺季加成每轮默认关闭。仅当用户在当前生成请求明确要求使用旺季加成时，向现有最终计算命令传裸开关 `--peak-boost-enabled`，不附带值；未明确要求时必须省略该参数，不传 `false`，历史持久开关为开启也不能自动加成。不自动弹旺季询问窗口；正常权限审批、店铺/平台/流程歧义确认仍保留。用户本轮明确指定天数时传 `--peak-boost-days <0～120整数>`，否则读取桌面保存的天数，保存值为空用30天。存储能力保留但不替代本轮授权；生成入口只读取一次配置快照，不修改持久设置，运行中保存只影响下一次读取。原备注触发条件、基础天数、120天上限和普通备货不变。
- AI“可供天数”追加在AH后：`=IF(OR(J2="",J2=0),"",(R2+T2+IF(Y2="",0,Y2)+IF(AB2="",0,AB2))/J2)`；全部MSKU写入，显示2位小数、保留计算精度，原S列保留。AD空白按A口径为0，合法数字/数字文本按克解析；非空解析失败报告原字段、MSKU、AD解析阶段及原因，不按0继续，也不称为下载失败。源销量/库存数字文本及有限负数保留，缺失/非有限/非法必需值仍明确失败，不新增负数阈值。

## 失败与恢复

- 每一步只把最后一条 `type="result"` 当作 terminal：先看 `ok`，业务数据读 `data`，附件读 `files`。运行中/session running 时等待原会话，不重复启动；`ok=false` 或必需字段缺失不继续后续步骤。
- 文件级核验失败与商品类型结论不同：来源信息损坏、缺文件、缺关键数值、重复 MSKU、覆盖不一致、批次冲突或无效快照时停止整轮，保留实际错误及定位信息；绑定核验未通过的商品行按A口径写全部公式，仍不得伪造核验通过或真实库存记录。说明失败步骤和恢复条件，不要求用户自行查找三个路径，不用旧文件或未知值填零替代失败输入。
- 店铺不匹配时保留实际“源数据核验店铺不一致”诊断及请求/快照名称；这只证明与输入不匹配，不能宣称店铺在生产系统不存在。
- 马帮业务命令按各自业务 Skill 的认证边界执行；深圳库存命令在内部按需恢复认证，终态失败后保留实际诊断，不额外刷新或重试业务。官方数据服务权限错误不刷新马帮 Cookie；缺授权、非认证接口失败、来源不一致或跨日不兼容时停止。
- 深圳库存终态失败时立即结束本轮，不继续货件查询和最终计算；保留实际诊断和本轮已取得源表，不要求用户自行准备三个文件，也不根据错误文本自行恢复认证或重复业务。

## 结果与交付

- 最终计算服务负责 Office Kit 重算及工作表、行列、公式存在性、全部行14列公式存在性和错误单元格检查。仅当最终 terminal `ok=true`、`data.formula_error_count=0` 且 `files` 有文件时，调用 `send_files(paths=<terminal.files>)`；该工具检查文件存在可读并发送，不负责 Excel 业务校验。发送成功后说明店铺、`source_data_time`、`row_count`；没有附件时不猜路径，发送失败只重试交付，不重跑生成。
- `ok=false` 时保留 `error.message` 及相关 `data`。若包含 `formula_error_count` / `formula_error_examples`，呈现真实单元格坐标和错误值；terminal `files` 可作为**失败诊断文件**发送，明确尚未通过验收，不作为正式可执行备货建议。
- 按已确认的 XLSX 规则，AA 在 V 或 W 为空时留空；AC 在 AB 或 AD 为空时留空，否则相乘。AD 表头为“单件重量(g)”，输入及总重单位为克。出现其他真实公式错误仍须报告，不通过 IFERROR、填零、删行或隐藏错误来声称零错误验收通过。
- Office 未配置（如 `LXE_OFFICE_NODE`）、重算失败或结果无法核验时，报告实际诊断并标记 **NOT VERIFIED**；不宣称真实重算、Microsoft Excel 原生验证或完整交付成功，也不自行修改宿主环境或安装依赖。
