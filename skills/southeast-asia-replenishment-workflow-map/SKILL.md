# 东南亚备货流程与数据准备

## 入口与范围

- 用户只询问流程时解释当前能力，不执行采集。
- 用户要求准备东南亚备货数据时，完成下面的数据采集与交付。要求完整东南亚备货时，先说明目前只能完成数据采集，再完成已授权的这一阶段；不把原始报表称为备货建议。
- 按用户明确的业务模块和已有上下文选择流程。只说“备货”且无法判断业务范围时，询问是 Amazon 还是东南亚，不凭国家名称推断所属模块。Amazon 备货使用 `replenishment-workflow-map`。
- 用户只要求上马导出或登录时，分别读取 `shangman-goods-export` 或 `shangman-login`，不扩大为完整备货任务。

## 当前数据源与衔接

| 数据来源 | 用途 | 采集 Skill | 实际产出 | 后续使用 |
|---|---|---|---|---|
| 上马 ERP | 当前配置账号可见的商品、库存和销量数据 | `shangman-goods-export` | 一份平台原始 XLSX，以及文件路径、工作表和数据行数 | 本入口交付采集结果；整理与备货计算尚未接通 |
| 雅仓 | 所选仓库的库存动销、当前库存及全局仓库产品资料 | `yacang-export` | 每仓每类一份原始 XLSX、文件路径、工作表和行数 | 交付采集结果，尚未接入备货计算 |

先按用户明确的数据源选择采集 Skill；仅说“准备东南亚备货数据”且上下文无法确定来源时，询问上马、雅仓或两者。不要默认同时导出两个平台，不跨来源合并报表。雅仓的数据类型、日期和仓库选择遵守 `yacang-export`；其成功及部分成功文件都交回本入口统一交付，说明失败和未执行范围。

`shangman-login` 为上马数据采集提供认证支持；需要登录时由导出 Skill 衔接，成功后回到导出步骤。登录本身不产生业务数据。

1. 选择上马时读取 `shangman-goods-export`，按其声明的 CLI 获取本轮原始报表。平台返回当前账号可见的全量数据，不承诺指定国家、店铺、仓库或日期的筛选；用户有筛选要求时遵守导出 Skill 的范围确认规则。
2. 上马已有有效登录态可以直接复用，不先重复登录。认证恢复、运行等待及错误处理都遵守对应 Skill，不套用马帮的 `lxeskill auth refresh`。
3. 接收最后一条 terminal 的 `ok`、`data` 和 `files`，保留实际文件路径、工作表、行数及本轮来源。不猜路径，不将导出时间声称为平台数据更新时间。
4. 当前流程到原始数据采集为止。由本入口调用一次 `send_files(paths=<terminal.files>)`，只交付所选数据源本轮 terminal.files 中的原始 XLSX；导出步骤已经交付时不重复发送。

## 边界与完成标准

- 不调用 Amazon 的店铺解析、销量分析、深圳库存、未关联货件或备货计算技能处理上马或雅仓报表。当前没有东南亚整理与计算步骤，不自行套用 Amazon 口径或编造算法补齐。
- 新增数据源或后续处理能力时，在本入口表中登记其用途、采集 Skill、产出及实际消费者；下载、认证和文件校验规则由对应 Skill 维护。只有已经接通的步骤才能执行，多个来源不得在缺少明确对应关系和使用规则时自行合并或互相替代。
- 成功说明已完成“东南亚备货数据采集”，报告来源、文件和数据行数；零行时明确没有商品数据，不推断为零备货需求。完整备货请求还需说明整理与计算尚未接通。
- 文件发送成功才称已交付；发送失败只重试交付。业务失败保留实际脱敏诊断及已完成阶段，恢复遵守对应 Skill，不擅自重复导出、不宣称整轮备货完成。
