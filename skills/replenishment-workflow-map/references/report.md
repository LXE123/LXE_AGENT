# V1 报表与字段参考

完整 terminal 外层使用 `type="result"`、`ok`、`data`、`files`。`data` 关键字段包括：`source_data_time`、`template_name`、`template_version`、`original_row_count`、`binding_verified_row_count`、`binding_unverified_row_count`、`row_count`（实际参与计算的行数，不等于首张表建议发货行数）、`link_count`、各建议分类数量（`air_urgent_count`、`air_count`、`sea_count`、`clearance_count`、`no_ship_count`、`sample_insufficient_count`）、`output_xlsx_path` 及三份实际输入路径。失败时读取外层 `error.message`，`data.exception` 仅为业务诊断。

## 工作表结构

结果文件包含 3 个业务 Sheet（`最终备货意见`、`本轮不备货`、`链接备货汇总`）和隐藏的 `源数据核验信息`，所有工作表列宽 15、行高 15 磅：

1. **`最终备货意见`（可交互试算表）**
   - 仅包含生成时建议发货且最终数量大于 0 的记录（含 `空运（急发）`、`空运`、`海运`）。第 1 行为说明，第 2 行为表头，第 3 行起为数据。
   - 空运、海运建议量已扣减马帮 FBA 总库存及本次传入的未关联货件快照（确认空快照按 0 计算），切勿再次扣减。海运同时需空运时，两列分别展示最终数量，运输方式显示 `空运＋海运`；预计总重量包含两者，单件重量缺失时留空并在提示中注明。
   - FBA 总库存只合计可售、待入库、预留、在途、待调仓、调仓中；计划入库与 90 天销量仅展示，不参与扣减或加权日销计算。品名优先使用本地 SKU 名称，商品备注保留在可编辑的“备注”列。
   - 深圳可用库存不足时仍保留算法建议量，“深圳库存缺口”公式列等于空运与海运建议量合计减去深圳可用库存（最低为 0，负库存按原值参与计算，库存未知或输入非法时留空并在“试算提示”说明原因）。

2. **`本轮不备货`（生成时快照）**
   - 合并暂不建议发货、样本不足和清货记录（`no_ship_count + sample_insufficient_count + clearance_count` 等于本页行数），按加权日销降序排列。
   - 前 37 列与 `最终备货意见` 同名同序（第 2 行为表头、第 3 行起为数据），末尾追加 `未备货原因分类` 和 `具体原因`。
   - 本页不参与公式试算：空运、海运最终建议量均为 0，补货天数、中间计算量、预计总重量、深圳库存缺口及输入检查留空；零日销的可销售天数留空，负库存与缺失保持原义。
   - 具体原因直接来自实际判断分支与生效参数（如清货、样本不足、FBA 库存或货件已覆盖、未达海运日销门槛、海运件数不足、海运未启用、未匹配海运分档等），不统一解释成库存充足。清货仅包含被清货规则排除的记录。

3. **`链接备货汇总`（生成时快照）**
   - 按 `父ASIN` 汇总（除清货外的所有参与计算记录），仅累计生成时最终建议发货的数量：`总补货量 = 空运（急发）补货量 + 空运补货量 + 海运建议量`（空运补货量含海运记录中的同时空运量；无发货建议的链接保留分组，四个数量列为 0）。

## `最终备货意见` 本行分步试算规则

- 修改浅黄色输入列（四段销量、FBA 库存分项、未发出货件总计、空运/海运补货天数、单件重量），浅蓝色公式列自动重算。修改仅影响本表，运输方式、日销分档以及其余两张快照 Sheet 保持生成时结果不变；数量归零仍保留该行。
- 补货天数后依次展示：`理论空运需求`、`理论海运需求`、`扣FBA后空运量`、`扣FBA后海运量`、`扣未关联货件后空运量`、`扣未关联货件后海运量`、最终 `空运建议量`、`海运建议量`。
- 海运天数是含空运覆盖期的总目标：`理论海运需求 = MAX(0, ROUNDUP(日销 × 海运天数, 0) - 理论空运需求)`。FBA 总库存和未关联货件均按“先扣空运、剩余再扣海运”的顺序逐级扣减。
- 所有公式只引用本行单元格，所选方案的 7/14/30 天权重和海运最低件数直接写入本行公式；`输入检查`（AJ 列）校验 `E:R` 与 `V:W` 共 16 个必填非负数值及正整数补货天数，`试算提示`（AK 列）动态提示海运最低件数未满足、深圳库存缺口或缺失、单件重量缺失等状态。
