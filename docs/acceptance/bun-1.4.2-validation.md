# Bun 1.4.2 升级验证

2026-09-12。在 Mac 开发，在 Windows 10 x64 真机验证。两端基线均为 `6f68879ae8e8b2942e6041636a2a92834493d0a0`，原 Bun 为 1.3.14。最终业务代码提交为 `7de16e18`，两端日常 Bun 已更新为 1.4.2。

## 改动

- Bun 与 `@types/bun` 精确固定到 1.4.2。锁文件只更新 Bun 类型包，没有批量更新业务依赖。下载使用 [官方 1.4.2 Release](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.2)，核对发布资产 SHA-256。
- Electron 保持 43.7.0，实际 Chromium 为 150.0.7871.250、Electron 内置 Node 为 24.21.0；独立受管 Node 与 Python 不升级。
- Windows 上复现 Bun FileSink 写入/刷新已返回、立即读取仍为空。使用标准异步文件流，并等写入回调完成后提供输出文件；保留容量限制和实际错误。原生写入对照 100 次出现 60 次提前读取，标准流对照无失败；修正后的业务组件 300 轮全部通过。
- 修正 Windows 测试的文件 URL、启动耗时预算、异步错误断言及协议文件换行。另修复完整 Python 验证发现的已有 Excel 句柄未关闭问题，避免更新资产时出现 `WinError 32`；测试明确 UTF-8，并按路径语义比较大小写。

## 隔离升级

使用独立应用 ID `com.lxe.agent.bun142.validation.b7dpmd`，测试版本为 99.0.1 → 99.0.2。现有已安装应用不被覆盖。

绑定和模型配置使用合成测试值，由真实 Electron safeStorage 加密。公司云端地址为本地不可用地址，验证的是绑定保存、解密和升级保留，不代表公司云端在线认证成功，也不替代真实马帮登录验证。

覆盖安装前后，`var/config/settings.json`、`secrets.bin`、`auth.json`、`var/db/agent.sqlite3` 和工作区测试文件的 SHA-256 全部保持一致。新应用实际版本为 99.0.2，能读取升级前的中文会话并继续解密绑定；三个服务健康状态均为 ready。安装后的 Agent SHA-256 与候选解包产物一致。
