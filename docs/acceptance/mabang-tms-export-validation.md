## TLS 诊断结论与边界

当时诊断环境为 Requests 2.32.5、urllib3 2.6.3、OpenSSL 3.0.16。成功与失败均请求允许的 `tms-cos.mabangerp.com` HTTPS 域名，`allow_redirects=False`，未观察到重定向；每个 GET 使用独立 Session、默认 adapter 零重试，未共享提交请求的 Token/Cookie。错误中的 `Max retries exceeded` 是底层异常文本，不能据此声称应用重试。

异常链为 `requests.SSLError` → urllib3 `MaxRetryError` / `SSLError` → `ssl.SSLEOFError(8)`；没有记录为超时、DNS 解析失败或证书验证失败。旧观测器没有逐请求耗时、DNS/TCP/TLS 分段、对端地址或完整堆栈，stderr 为空；整轮耗时不能当失败 GET 耗时。响应返回前失败排除了本次在 `iter_content` 接收正文后抛错，但不能区分握手和等待响应头。

禁网回放分别在 `_validate_conn` 和 `HTTPSConnection.getresponse` 注入同形 SSL EOF，都得到相同摘要、单次调用且零 DNS/外网连接。这只证明摘要无法定位真实阶段，不证明线上两种情形均发生。另有真实 Requests/urllib3 的流中断、Content-Length 不符回放，验证错误传播、响应关闭及先前批次保留。

未找到必须修改 TLS、Session、代理、DNS、超时或流式处理的证据；当时连接/读取预算为 5/30 秒、证书验证开启，本地配置检查未见代理或自定义 CA，但失败时完整网络路径未知。不能归责某个服务端、代理、IP 或本地 TLS，也不能因后续完整导出成功就认定根因已修复。

没有同一链接重复 GET、有效期或一次性限制的证据。两轮第一批字节相同也不证明同一 URL 可重放，继续保持下载不自动重试。

补充的安全日志经禁网测试核对，复用原日志系统，记录 `service=mabang_tms_file`、`elapsed_ms`、`http_status`、`stage`、`exception_type`、`reason`。未取得响应时状态为 null、阶段为 `unknown`；耗时包含 GET 和流读取，不含提交或 Excel 处理。地址、凭据和签名脱敏，日志失败不覆盖业务结果；新日志未追溯补造旧请求细节。回归见 [TMS 测试](../../python/lxeskill_cli/tests/mabang_tms/test_mabang_tms_export.py)。
