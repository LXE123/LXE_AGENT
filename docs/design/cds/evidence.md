| 页面部位 | 保存的代码证据 | 片段 ID |

## Claude 是否有类似的设计 Skill

**有面向模型的 CDS 指导材料和生成流程的直接线索；公开设计 Skill 也确实存在。两者要分别看。**

| 证据 | 能下的结论 | 不能直接推导的结论 |
| --- | --- | --- |
| S1 首行：`@generated by apps/cds-docs/scripts/gen-cds-skill.mjs from packages/cds/{CLAUDE.md,docs/**}` | 这份材料注明由命名为 `gen-cds-skill` 的脚本从内部文档生成 | 未取得脚本实现，不能声称知道其全部生成／安装流程 |
| S1 的 `Claude-native` 段落说明设计系统也供 Claude 编写，并称 `CLAUDE.md` 是 system prompt，组件文档为检索组织 | 上游文档明确表达了供模型使用的设计意图 | 这是文档的自述，不是对某次会话真实 system prompt 或加载时机的抓取 |
| Anthropic 公开的 [frontend-design/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) | 官方公开仓库有通用前端设计 Skill，指导视觉方向、字体、布局和自查 | 通用前端设计 Skill 不等同这份内部 CDS 规则，也不证明 Claude 桌面壳由它生成 |

公开来源核对日期：2026-10-19。这里只保存链接和结论，没有把该公开 Skill 安装到项目，也没有创建 LXE 的新 Skill。

因此，若问题是“他们会不会也把设计规范整理成 AI 可以按需读取的指导材料”，答案有很强的直接证据。若问题是“是否已经拿到了完整的、可独立安装的内部 CDS Skill，或证明设置页由它自动生成”，目前还没有。

## 已知冲突与缺口

1. **色阶数量**：S1 写每个色相 36 档；本次 D1 实际是 9 色相各 35 档，共 315 条。保留双方原样，不补造缺失色阶。
2. **图表表面示例**：[Data visualization](sources/embedded-text-8.original.md)暗色 `surface-1` 示例是 `#1a1a19`；S1 的映射对应 `#151515`。可能涉及材料版本或场景差异，原因未验证。
3. **声明数不等于规则数**：2070 条声明、952 个名称含重复选择器和内部变量，不能宣称找到 952 条公开颜色规范。
4. **前缀与组件变体**：vanilla 的无前缀 token、React 的 `--cds-*`、组件 `variant`、LXE 的自定义别名不是一一同名等价；需要看具体映射。
5. **完整标准文件**：取得了生成规则文档和具体实现资源，但未取得完整 `packages/cds/` 源码、完整组件文档库、设计稿或所有运行时状态。因此只能说“有明确的规范材料”，不能说“所有标准已查齐”，也不能断言“根本没有标准文档”。
6. **自动使用 Skill**：尚未追踪内部 CDS 材料的全部加载条件、会话调用记录或生成设置页的历史。名字中有 skill 是线索，不是这些行为的证据。
