# 赛狐通过设备访问

桌面 Agent 的受管 `lxe-saihu` MCP 连接使用 `X-LXE-Client: cli`，由服务器按 WireGuard 来源设备和当前 `saihu` 权限授权。无需业务 Token、桌面身份检查成功或先运行 `cloud-context`；Skill 范围与业务授权分别处理。

MCP 仍由 Bun 运行时直接连接。原生连接使用直接 HTTP/HTTPS socket，忽略系统代理，不发送 Authorization/Cookie，不保存 Cookie、不跟随重定向。流式结果和实际错误继续交给 MCP SDK。其他 MCP 连接器保持原行为。

升级自动迁移可识别的官方配置，包括历史 localhost 和公司地址，以及两种旧 Bearer 环境变量或对应 Authorization 占位符。连接器开关、工具限制、超时和其他普通头保留；默认连接器仍关闭。

自定义 URL、密钥、Cookie 或鉴权映射不改写；日志会明确提示需要核实且不会打印凭据。原生标记与自定义认证同时存在时拒绝连接，不回退旧鉴权。

服务器须先部署。38 个已登记普通 HTTP 操作和 MCP 支持新方式；网关状态、报表同步管理仍使用管理鉴权。新方式失败后不会尝试旧凭据，管理员设备也需要业务权限。

独立飞书网关本轮不改，服务器仍兼容旧 Key 和业务 Token。统计上传还依赖业务 Token，因此桌面整体凭据申请、刷新和兼容环境变量继续保留。赛狐上游凭据仍只存服务器。

验收使用隔离 PostgreSQL 和模拟上游，覆盖停用、发布收权、已建立 MCP 会话后拒绝后续调用、原生边界、旧方式兼容及流式取消。线上只查询接口目录、工具列表或已核实的读取操作，不做生产写入或收权；不生成桌面安装包。
