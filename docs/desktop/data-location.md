# 程序与用户数据

Windows 安装版默认把数据放在 `%LOCALAPPDATA%\LXE Agent`，默认工作区在其中的 `workspace`。程序可以安装到其他盘；同一 Windows 用户换安装位置后仍使用同一份数据。开发和源码预览继续使用当前 checkout 的 `var`。

需要独立数据集时，在启动前设置绝对路径 `LXE_DATA_ROOT`。该路径必须与程序目录分开；显式指定后不会自动导入其他位置的数据。此选项只选择启动时的数据位置，不提供运行中的搬家功能。路径无效或不可写时会显示实际错误。

## 旧版第一次启动

新数据目录尚未初始化时，桌面查找程序旁的 `var` 和安装器记录的原安装位置。只有一份旧数据则自动复制；多份则让用户选择。没有旧数据就初始化新目录，已有新数据则直接使用。

迁移时必须退出旧程序及其子进程。桌面先在独立启动目录运行，将旧数据复制到新位置旁的暂存目录，校验文件、数据库及加密凭据，修正受管的内部路径，再一次性启用新目录并重启。凭据由独立 Electron 进程使用复制出的原用户资料校验，避免使用临时启动资料中的另一把密钥。默认工作区也会迁移；外部工作区不移动，历史正文和命令不改写。临时文件、缓存、进程锁重新生成。目录链接会明确报错，不跟随复制。

原 `var` 始终保留。失败时新数据不会启用，错误中包含暂存副本和诊断文件路径；修复原因后重新启动即可重试。失败副本不会被当作正常数据，也不会自动覆盖已有新数据。迁移后的程序与旧版副本各自继续写自己的数据，不会双向同步。

## 安装和卸载

手动安装可以改目录，旧目录完整保留，快捷方式和注册信息指向新安装。应用内更新固定原程序目录。已有 `var` 在同目录替换程序时仍原地保留。

卸载只删除程序，始终保留共用数据、旧 `var` 和 WireGuard 配置。旧的 `/DELETE_LXE_DATA=1` 参数不再删除数据。新版旧副本的卸载器会检查注册信息归属，避免移除新安装的快捷方式；更早版本的卸载器行为无法追溯修改。

安装开始执行后仍不提供取消操作。升级鉴权、差分下载、安装包缓存和服务器接口不受此调整影响。

## 实现边界

桌面负责复制、发布目录以及迁移配置和 Gateway 数据；安装包内 `agent-cli relocate-data --copy <暂存目录> --source <旧数据目录> --target <最终数据目录>` 负责 Bun 运行时数据库、会话文件和派生索引；`python -m shared.db.relocate_data` 只处理 Python 自己的 `lxeskill.sqlite3`。离线入口只应对暂存副本执行。

迁移完成标记位于 `migrations/data-location-v1.json`。启动锁和失败诊断位于数据目录旁，因此加锁不会提前初始化目标目录。迁移范围只涉及本地数据位置，不改变设备身份、不重新创建 WireGuard 隧道，也不引入数据库降级或启动健康回滚。

源码与 Windows 隔离安装验证结果见[验证记录](../acceptance/data-location-validation.md)。
