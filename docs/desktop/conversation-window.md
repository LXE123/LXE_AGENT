# 工作区、对话与历史窗口

实时 batch、发送中的用户消息和 transcript 通过同一投影生成有序展示项。消息保存只更新该项，不再根据历史读取时间撤掉临时气泡。

用户输入以 client_message_id 关联发送、activity 与历史，服务端 message_id 仍独立保留。模型正文与思考沿用 message.id:contentIndex，工具使用 tool:callId。旧历史在读取时根据展示组和组内不可变消息位置生成 display_id，不修改原文件。环境上下文通过结构化来源标记隐藏，用户正文中的同名标签不会被过滤。

## 工作区与对话

侧栏按会话的完整工作目录分组。点击顶部“新对话”使用设置中的默认工作区；点击某个工作区旁的加号则使用该目录。首次发送前，可在对话顶部选择已有工作区，或通过文件夹选择器选择其他目录。进入新对话时，Runtime 创建或复用该目录的空会话，不调用模型。首次消息成功受理后成为普通会话；空会话只显示当前选中的一条“新对话”，不进入搜索和历史统计。

默认工作区沿用应用数据目录下的 `workspace`，也可在设置中修改。多个对话共用该目录；修改默认设置只影响之后新建的对话。已经发送消息的对话继续使用创建时保存的目录，顶部提供“用应用打开”，不能直接换目录。目录失效时显示实际错误，不会换到默认目录继续执行。

选择有效目录后立即登记工作区，进入该目录的新对话草稿；从对话顶部选目录时，文字和附件带到目标空会话；目标已有草稿则合并，超限或附件仍在载入时保留原状态并提示。原会话的终端和浏览器不搬动。取消选择不改变草稿，登记失败显示实际错误。即使没有发送过消息，或删除了最后一个会话，工作区也会保留并显示“暂无对话”。默认组始终排第一，其余按最近会话活动时间排序，没有会话时按登记时间排序。展开后按组分页，置顶只在组内生效。搜索跨工作区，并标出结果所属目录。

工作区行的操作菜单可以重命名，包括默认工作区。名称去除首尾空白，留空恢复自动名称；允许重名，通过完整路径区分。名称同步显示在侧栏、目录选择器和对话顶部，只影响显示，不改变磁盘目录或执行路径。默认工作区始终保留独立的“默认”标记。修改默认目录后，旧工作区和名称保留，标记转移到新目录。

各组的折叠偏好按完整目录保存到本机界面存储，刷新、重启、搜索和数据更新都会保留。主动打开对话、选工作区或新建对话会展开对应组，并记住这个状态。尚无偏好时展开默认组和当前活动组；存储损坏或无法写入不会阻止使用。

侧栏展开时可拖动右侧边界调整宽度，范围为 256–420px，初始宽度为 280px。宽度保存在本机，收起再展开、刷新和重启都会保留，悬浮预览也沿用该宽度。窗口空间不足时临时缩窄显示，不覆盖保存的宽度。

会话标题的生成、手动改名与恢复规则见 [会话标题](../harness/runtime/session-titles.md)。

会话仍在 Bun 的 SQLite 中保存 `directory + worktree`，轻量登记表 `agent_workspaces` 只保存目录主键、可空显示名称和创建时间，没有额外工作区 ID 或会话成员列表。升级时从历史会话补齐登记，无需目录当前可访问；运行时启动时登记当前默认目录，之后创建会话也会确保登记存在。`workspaces.register` 校验并规范化目录，重复或符号链接路径复用已有登记和名称；`workspaces.rename` 更新显示名称；`sessions.workspaces` 联合登记与会话返回名称、时间、会话数及空工作区。注册和改名沿用 Dashboard RPC 与 sessions 刷新通知。`sessions.create` 校验目录并原子复用空会话；旧记录不会因为没有消息而被隐藏。`sessions.list` 排除空会话并支持可选 `directory` 过滤；`sessions.send` 仅在创建新会话时接受 `directory`。同一 Git 仓库中的不同子目录分别展示，底层继续复用现有 Workspace Instance 和指令加载机制。选目录不会自动生成项目配置或初始化 Git。

### 用应用打开目录

新旧对话顶部、右侧文件树顶部使用同一个分体按钮：点左侧图标，用当前应用打开目录；点右侧箭头，选择其他已安装应用并立即打开。启动请求成功后才记住选择，所有会话和两处按钮共用本机偏好。第一次使用默认 Finder／资源管理器，只有一个可用应用时不显示箭头。左侧工作区列表仍直接打开系统文件管理器；单个文件仍遵循文件关联，与目录偏好分开。

应用目录与检测规则参考 DeepSeek Harness `639ed01539`（MIT），覆盖其 macOS、Windows 编辑器、IDE、Git 客户端和终端条目，菜单只列出本机检测到的应用。检测及图标在主进程缓存；失败可重试。卸载或移动启动器后，下次打开会重新检测该应用一次；不可用则回到系统文件管理器。错误保留实际诊断，图标提取失败使用通用图标。

桌面桥接新增 `desktop.getWorkspaceApplications({ refresh? })`，`desktop.openWorkspace(directory, applicationId?)` 的应用 ID 可省略，省略时保持系统打开行为。主进程校验调用方和目录，只接受内置应用 ID，用参数数组启动，并清理凭据及应用运行环境。外部应用独立运行；成功仅表示启动请求已接受，不保证窗口已加载完成。不会修改系统默认应用，也不连接内置终端、浏览器或 Agent 工具。两平台结果及复现入口见[验收记录](../acceptance/20261002-workspace-applications.md)。

## 阅读窗口

首次读取最近 10 个展示组。向前使用 message_before，向后使用 message_after，二者互斥。游标始终由服务端解析。group_cursors 包含页中的全部展示组，包括只含内部上下文的组，过滤正文不会破坏分页。

阅读窗口限制为 60 组和 16 MiB 序列化消息载荷；整组淘汰远离视口的一端。可见组不淘汰，单个超大可见组和当前生成允许暂时超限。这个预算不等于浏览器总内存。历史页直接并入窗口，不额外存一份 Query 缓存。最新页另保留 10 组，阅读旧历史时通过“跳到最新”切换，不拼接不连续的窗口。模型压缩不删除显示历史。

TanStack Virtual 3.14.10 按稳定展示 ID 测量动态高度，视口两侧各预渲染 5 项。上拉和窗口裁剪由可见项身份与偏移保持位置。浏览器原生 overflow-anchor 关闭，避免两套补偿叠加。用户在底部时跟随生成，阅读历史时不跟随。折叠状态在会话层保留，测量缓存随窗口淘汰。

完成请求的成功载荷由历史确认后释放实时副本；失败尝试只在当前会话保留，不增加失败消息历史体系。

## 问题卡片

桌面回合等待 `ask_user_question` 时，问题卡片暂时代替普通发送入口，保留原聊天草稿。自由文字写在卡片中，通过专用接口提交；失败保留答案并显示实际错误，确认后恢复普通输入。切换会话或界面刷新后重新查询 Runtime，已完成或失效的问题不能再次提交。卡片提供“停止本次任务”，不默认选择答案。生命周期和验证见 [结构化提问](../harness/runtime/tools/ask-user-question.md)。

## 文件引用与截图

回形针、拖放和复制粘贴已有文件都只注册本地路径，不读取全文或复制文件。不限文件数量、大小与扩展名，目录和符号链接不接受。同一路径在草稿中只显示一次，文件名下方显示大写后缀；没有后缀的文件不显示这一行。发送前重新检查可读性，Agent 读取时取得当前内容。已有图片文件也通过 `read` 按需查看。

没有路径的剪贴板图片保存到应用数据目录下的 `attachments/screenshots/<uuid>.png`（目录位置见[程序与用户数据](data-location.md)），草稿显示缩略图。每条消息最多粘贴 5 张截图，本地文件引用不占用截图额度。每张截图的源字节与保存后的 PNG 均最多 20 MiB，图片最多 4000 万像素。发送时附加本地文件引用与模型图片块；原始 transcript 保留图片内容，桌面历史 DTO 不直接携带 Base64。保存与读取规则见 [图片持久化](../harness/runtime/context/context_persistence.md#图片与敏感数据)。缩略图和路径去重标识仅用于草稿，不进入发送载荷。

截图保存期间可以输入文字，但不能发送。多个接入操作即时捕获内容、按操作顺序显示，切换会话后丢弃旧结果。待发送附件不按时间过期，发送失败保留当前草稿和截图供重试；移除、会话切换或退出时的清理，只删除未发送截图，不删除用户文件。发送期间的清理延迟至投递完成；已经接受的截图永久保留，本期不做历史附件回收或重启草稿恢复。

Electron 43 的 DOM 文件对象与原生剪贴板文件列表分别处理：选择和拖放通过 `webUtils.getPathForFile`，粘贴先读取原生文件列表，文件引用优先于附带的图片预览。Main 在文件剪贴板格式存在时使用 macOS AppKit 或 Windows Forms 获取路径；普通文字保持原生粘贴，文字路径不会自动变成附件。系统读取与文件操作失败保留实际错误。

输入框里的截图显示为统一的 54×54 圆角缩略图。生成时先从原图中心裁出方形，再高质量缩小到 256×256；小图不放大，保存的完整 PNG 不裁切，避免宽图或长图先缩小后再撑满卡片造成模糊。删除按钮覆盖在右上角，不显示分组标题、截图名称或后缀。附件保持一行，超宽时横向滑动；普通文件保留名称和后缀。点击截图复用大图弹窗，Main 仅凭暂存附件 ID 按需生成最长边 1600 像素、保持完整比例的预览；关闭后释放草稿预览，迟到响应不重新打开弹窗。预览失败显示实际错误，暂存和发送流程不受预览影响。

发送后的用户消息按“图片缩略图、文件卡片、文字气泡”从上到下靠右显示。图片和文件各占一行，超宽时横向滑动；每行内部保持添加顺序，没有内容的区域不显示。点击图片可放大，按 Escape 或点击遮罩关闭；点击文件卡片打开侧栏预览，独立的“用应用打开”按钮使用系统应用。入口与支持格式见 [文件预览](file-preview.md)。

图片预览按可见范围加载，Main 通过会话和附件 ID 获取图片，按原图比例生成最长边 320 像素的缩略图或 1600 像素的放大预览。预览源限制为 20 MiB、4000 万像素，仅限制内嵌预览，不限制文件引用与系统打开。优先使用历史中保存的图片内容；未保存图片内容时，再查当前轮次的待持久化附件或本地文件。不能因为原文件删除或变化，就判定已有历史图片不可预览。生成的缩略图不作为新的模型输入；无法取得图片或生成预览时显示实际错误。

### 附件验证

定向测试覆盖数 GB 稀疏文件、整批拒绝、截图回滚、路径去重、发送持有、会话切换和模型输入分流。`apps/desktop/test/fixtures/conversation-paste.electron.ts` 是可选的 macOS 原生验证入口：用 Bun 将它和生产 preload 分别构建成 CJS（external electron），再以 Electron 执行，参数为 preload 的绝对路径。脚本保存并恢复原生剪贴板，检查单文件、多文件、图片文件与截图加文字的实际粘贴事件。

额外传入 HTML 页面路径可验证真实输入框；页面加载 Bun 构建的 `apps/dashboard/test/features/sessions/composer-fixture.tsx` 及其 CSS。该页面不调用真实模型。历史平台验证范围见 [对话界面验收记录](../acceptance/conversation-window-validation.md#原生附件输入)。

## 历史窗口验证

从仓库根执行定向 Bun 测试，浏览器 fixture 位于 apps/dashboard/test/features/sessions/window-fixture.html。在 dashboard 的 Vite 服务中打开此页面，不连接桌面 IPC 或真实模型。

fixture 提供 1000 个展示组、工具输出、Markdown、动态图片和发送交接按钮。验证时检查气泡交接不重复、不换节点，窗口预算与超大可见组例外、分页及动态高度的锚点保持、阅读历史时不跟随尾部更新、工具展开状态和切换会话后的旧响应隔离。算法测试与实际浏览器验证分别覆盖数据规则和 DOM、测量、滚动行为。

过去的实测值与证据范围见 [历史窗口验收记录](../acceptance/conversation-window-validation.md#历史窗口)，不作为任意真实会话的内存或像素保证。

## 执行过程整体折叠

思考、中间说明和工具按出现顺序组成执行过程，正文直接显示，工具详情独立折叠。运行期间默认展开，成功完成时收起一次；之后用户重新展开不会被重复终态或持久化交接覆盖。失败、取消默认展开，错误状态放在始终可见的过程标题中。最终回答、用户气泡和最终附件不进入过程折叠区域。

过程展开后仍按块虚拟渲染，标题和原始块都有稳定身份。手动展开保持标题锚点，自动收起时保留阅读锚点或底部跟随。`process-fixture.html` 可在本地 Vite 下验证状态转换，检查展开与收起时的锚点、工具独立展开状态，以及重复终态不覆盖用户操作。历史实测见 [过程折叠验收](../acceptance/conversation-window-validation.md#过程折叠)。

## 气泡对齐与产出文件位置

用户消息通过自身的自动起始边距在虚拟行内右对齐，不依赖祖先的 flex 布局。产出文件仍从历史消息的 artifacts 读取，展示时按 turn 汇总、按 artifact_id 去重，使用稳定的 turn 文件列表身份，放在当前 turn 内容尾部。过程收起不隐藏文件，工具产出文件的时间不决定卡片在最终回答中的位置。

浏览器验证应覆盖短消息、长消息、附件、窄窗口和持久化交接，检查右对齐、横向溢出，以及过程收起后的文件位置。历史实测见 [气泡与文件验收](../acceptance/conversation-window-validation.md#气泡与文件)。

## 紧凑过程排版与用时

思考正文仅在展示层按空行分段，段间 6px，段内换行与缩进保留；过程块间距 6px。过程标题内边距只保留一层 4px，标题行与最终回答之间留 8px，最终回答不再叠加顶部外边距。对话用时独立格式化为 8m6s、1h2m3s，省略零单位，统计页保持原有格式。历史实测见 [过程排版验收](../acceptance/conversation-window-validation.md#过程排版)。
