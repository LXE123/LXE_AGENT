# 云端权限兼容与迁移

本文说明历史授权缓存的兼容，以及服务器与客户端的协调升级。日常权限查询见 [桌面云端接入](cloud-access.md#权限刷新与缓存)。

## 备货类型兼容

当前 Skill 类型为 `replenishment`，中文“备货”、英文“Replenishment”。类型名称转换不改变 Skill 名称、目录和 CLI `lxeskill replenish …` 命令，也不改变业务权限、设备身份或网关凭据。

桌面只在读取已校验的历史权限缓存时把 `amazon_replenish` 转成新名称，保留绑定、版本和验证时间，不把缓存当成新验证结果。在线权限仍来自服务器，不会根据旧名称追加新授权。服务器必须配套迁移当前模板并递增发布版本。

本地 SQLite 和云端统计在分类汇总时把旧名称归入 `replenishment`。技能数和回合数在合并后的分类内去重，调用次数继续累加。原始记录中的类型名称保留，上传确认和进度不变，不需要清库或重新上传。该统计转换不参与权限判断。

## 同步升级与回退

仍从旧版升级时，安排维护窗口，暂停受影响客户端与模板编辑，备份后先更新服务器并执行 `0037_replenishment_type` 迁移，再更新客户端。核对权限查询、受影响技能的加载、历史混合统计和离线补传。不要在新旧客户端混用期间承诺备货可用。

回退须协调服务器和客户端版本。服务器反向迁移追加更高版本的旧名称快照，不覆盖历史。回退客户端后重新查询权限；若旧客户端不能读取新格式缓存，仅清除权限快照后验证，不能清除设备身份、业务数据、统计文件或上传进度。完整服务器步骤见服务器仓库 `docs/replenishment-type-rename.md`。
