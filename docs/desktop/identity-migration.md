# 旧设备身份自动迁移

升级前已接入的设备可能仍持有 `lxe_dev_` 凭据。新版桌面在启动和公司云端重连时检测这种状态，自动迁移，不需要重新导入设备文件。服务器必须先部署迁移接口并为全部有效旧设备建立授权。

桌面主进程先在系统安全存储中生成并保存 `cloud_identity_candidate`，再准备和确认迁移。候选身份只在主进程使用，不进入 Agent、CLI 环境或日志。服务器确认成功后才把它设为当前身份，并刷新业务凭据。设备 ID、既有实例、VPN 和业务配置保留。

断网、退出或确认响应丢失时，待启用身份仍留在安全存储中。下次连接先查询服务器的迁移状态，继续原候选身份。不会生成第二个候选身份覆盖第一次准备，也不会因本地最后一步保存失败而丢失服务器已启用的身份。

公司云端显示“身份迁移中”和具体失败原因。未部署接口时提示服务器不支持；未授权、实例不一致或凭据丢失时提示相应异常，不再显示成普通“未配置”。服务器上的异常登记需要管理员恢复，桌面不会凭 IP 推测管理员身份。新接入文件和手动切换绑定会清除原绑定的待迁移身份。

发布必须先更新服务器，再升级桌面。Windows 真实安装环境应验证：旧绑定自动迁移、退出重开恢复、迁移后的 ERP 查询、设备和 VPN 信息保留。仅在 macOS 跑 `win32` 配置测试不能代替 Windows 真机联调。
