# 桌面 exec 实时输出

命令运行时，已经写入 stdout/stderr 的内容会更新原来的工具块。`exec` 提前返回、对话结束或开始下一轮后，后台进程仍然更新原工具块。子进程自己缓冲、尚未写入管道的内容无法提前显示。

## 数据流

进程管理器读取输出后，通过独立的 `onExecUpdate` 回调通知 Agent CLI。首次输出立即通知，后续按 100 ms 合并；每个进程最多一个正在发送的通知和一个“有新内容”的标记。退出并排空管道后发送最终快照。原来的 `onExecComplete` 仍只通知已经让出执行的进程完成，不与实时回调重复绑定。

Agent CLI 使用同一展示转换函数生成实时事件、恢复查询和历史页面中的进程预览。桌面协议升级为 **24**：`background_task.changed` 支持 `running`，包含进程 `revision` 和已转换的 `step`；`sessions.execTasks` 提供会话进程快照。

桌面桥接通过独立 IPC 事件推送单个工具更新。运行中事件不刷新历史，也不发送完整对话。前端按会话、轮次、工具调用和进程 ID 保存最新版本，随后覆盖对应工具行的展示；模型流序号不参与进程输出版本比较。旧事件不能让终态退回运行中。

## 容量与恢复

- 输出预览沿用 2,000 字节尾部预算，省略内容时明确标示。实际保留容量和输出文件机制不变。
- `exec` / `wait` 的读取游标和模型正文保持原样。实时预览不写入数据库或增加工具结果消息。
- 前端最多保存 64 个进程快照，离开会话时释放。进入会话、连接恢复或窗口重新获得焦点时，先订阅再读取快照，按版本合并期间收到的事件。
- 运行时重启后，只能恢复新运行时仍保留的进程；其他内容继续使用已有历史记录。无需数据库迁移。
- 桌面和 Agent CLI 必须使用相同协议版本；不修改飞书卡片与 lxeskill CLI。

## 验证入口

新增的 `exec-live-output.test.ts` 覆盖真实子进程的提前输出、慢消费者、UTF-8/GBK、交错输出、失败、终止、容量限制，以及前端乱序和恢复。Runtime 测试使用模拟模型，确认对话结束后仍有输出更新，且保存的工具结果不变。协议、服务查询、桌面桥接与历史转换测试覆盖传输和恢复路径。

测试均从仓库根执行。Windows 使用独立领取的工作区及相同提交，不更新主工作区部署，不运行实际业务上传。
