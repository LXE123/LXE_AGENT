# 客户端身份与后台登录

`desktop:dev`、`desktop:preview` 和正式包采用相同的接入方式：桌面安全存储中的独立凭据验证身份，服务器决定管理角色、业务权限和模型目录。启动方式、电脑名称、环境变量中的共享密钥都不赋予管理员身份。

## 使用方式

在云端接入页面导入新版加密接入包。新设备使用 v5 包建立受管 WireGuard 连接；保留已有手工隧道或更换凭据使用 v4 包，不重新安装隧道。v1–v3 旧包会要求重新签发，防止把原先暴露给 Agent 的设备 Token 当成新版管理凭据。

桌面启动即验证身份，此后默认每 60 秒同步服务器角色和权限。管理员点击“打开管理后台”后进入外部浏览器；服务端交接码 60 秒内只能兑换一次，页面立即从地址中清除它。后台会话只保存在浏览器内存，刷新后需要从桌面重新进入。电脑名称变化不改变身份；删除或复制随机 `machine_id` 不能获得另一主体权限。

## 凭据边界

独立身份凭据只由桌面主进程读取，通过现有系统安全存储保存。Bun runtime 和 Python CLI 只收到用途受限的 `lxe_run_` 业务凭据，以及独立的 `lxe_erp_run_` ERP 凭据。主进程不向子进程传递身份凭据或后台会话，也不再从 preview 环境挑选管理员密钥。

桌面向 `/api/v1/agent-data/identity` 获取身份和权限，向 `/identity/business-credential` 获取业务凭据。有效期为 24 小时，剩余不足一小时续期；正常续期保持 Token 不变，避免中断 Agent。服务器每次业务调用检查当前权限与父凭据。换证后旧凭据立即失效，其它设备不受影响。

管理入口只控制展示。管理员角色、设备状态和 WireGuard 来源均由服务端在每次管理请求时重新检查。管理员即使只有补货业务权限，也可以使用管理后台；本机 Agent 仍只获得补货权限。

断网时显示连接无法验证，不能申请后台会话。本地权限缓存与离线业务策略继续沿用现有规则。身份和会话不在 Python 侧建立影子表。该边界不承诺隔离同一操作系统用户下的任意 Shell。

## 统计迁移

`machine_id` 继续用于统计聚合。服务端记录每次新上报认证得到的主体，并同时保留旧设备登记历史；旧记录没有认证信息时显示“历史身份未知”。不能用某条旧设备的撤销状态代表整个实例，也不应把历史上传批量归给新登记。

服务端先部署身份接口，再导入新凭据。管理员迁移完成后关闭 `LXE_LEGACY_ADMIN_AUTH_ENABLED`；仍有旧业务客户端时暂时保留独立的 `LXE_LEGACY_CLIENT_AUTH_ENABLED`，逐台迁移后关闭。
