# 越南库存与动销合并报表实施计划

**目标：** 用户请求越南合并库存或动销时，交付与菲律宾相同格式的两份两表 XLSX，来源为雅仓 VN8806 和马帮 TMS VN1。

**分层：** 第一层在既有菲律宾流程中提取可配置的共享编排与双文件生成能力，保留菲律宾公开命令、原文件与续跑合同。第二层基于第一层接入越南固定来源、独立命令、产物目录和 Skill。两个评审层按 stacked PR 串行；本次不执行 Git 提交。

1. 对照菲律宾现有端到端和工作簿测试，先增加共享化前后的行为回归：来源、两个文件与两张表、样式、SKU 匹配及过滤、失败不交付、续跑和来源范围。
2. 提取最小国家配置，将仓库、名称、产物目录注入既有流程；菲律宾入口提供原配置。所有错误、恢复、TMS 空仓和原有目录保持兼容。执行菲律宾报表、雅仓和 TMS 定向测试。
3. 仅在第一层验证正确后，以越南配置复用同一实现，添加 `vietnam reports export` 命令、数据集和 Skill 路由；明确独立于越南备货模板，任一合并报表请求均交付两份。验证 VN8806、VN1 仓库与 ID 使用已有导出契约。
4. 使用模拟 HTTP 和真实 XLSX 测试两国端到端、两个工作表和字段内容及样式、来源校验、失败和续跑；运行 Python 命令契约及 Bun 归属测试。真实 ERP 和 Windows 未验证时明确记录。
5. 逐层检查 diff、`git diff --check`、敏感信息及 Git 状态，更新 handoff；按授权分别申请暂存和提交，后续推送、PR 再分别确认。
