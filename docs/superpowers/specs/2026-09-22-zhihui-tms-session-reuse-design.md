# 智汇 TMS 登录态复用设计

## 目标与边界

智汇 TMS 的商品导出在 Desktop 重启后仍可复用有效的 `apiToken`，避免每次执行导出都调用登录接口。缓存只服务智汇 TMS，且只对已启用生产调用、账号与密码均已配置的 Desktop 生效。

不改变商品导出的确认、分页、文件投递或账户级互斥行为；预览不读取网络或登录态。不会把 token 写入普通文件、标准输出、日志、聊天结果或 Git。直接运行 Python CLI 且没有 Desktop 会话服务时保持现有的“一次执行一次登录”兼容行为。

## 架构与职责

Desktop 主进程新增一个仅回环地址可访问的智汇会话宿主。它复用现有 `AuthBrowserHost` 的安全边界：随机 256 位能力凭证、`127.0.0.1` 随机端口、`Authorization: Bearer` 恒定时间比较、拒绝浏览器 `Origin`、请求体大小限制、`Cache-Control: no-store`，并在 Desktop 停止时关闭。

宿主只暴露三项固定操作：读取当前账号绑定的 token、保存新登录得到的 token、清除当前账号 token。它不代理智汇业务接口，也不承担登录或导出，因此不把平台业务协议耦合进 Desktop。

Desktop 配置仓库在现有由 Electron `safeStorage` 加密的 `secrets.bin` 中增加智汇会话记录：账号规范化值的 SHA-256 指纹、token、写入时间。账号本身不重复存入会话记录。会话记录不进入 `settings.json`、设置页状态或环境诊断输出。

Python 侧增加一个小型 `ZhihuiTmsSessionProvider`：从受控环境变量发现宿主、通过能力凭证调用三项操作，并在宿主不可用时无状态降级。`ZhihuiTmsClient` 只接受初始 token 和一个受控的失效回调；它不知道 token 的存储位置。这样未来需要登录态复用的平台可采用相同的 provider 边界，而不需要修改商品导出链路。

## 数据流

1. Desktop 启动会话宿主，并仅向 Agent/Gateway 及其子进程注入宿主 URL 与能力凭证；凭证不显示给 UI 或模型。
2. 执行导出仍先取得现有账户锁。锁内的 provider 读取与当前账号指纹匹配的 token；匹配时客户端直接调用智汇 API，不发起登录。
3. 缓存缺失时，客户端按现有低频、限次规则登录；成功后通过 provider 写回 Desktop 加密存储，再进行导出。
4. 账号、密码变更、清空智汇配置或禁用生产调用时，Desktop 在同一加密写事务中删除会话记录，防止跨账号或旧密码复用。

## 失效与风控

只有智汇业务请求返回明确 HTTP `401` 时，客户端才会清除缓存、重新登录一次，并只重放被 `401` 拒绝的请求。因为服务已明确拒绝该请求，不会产生重复的导出副作用。

`403`、`429`、网络异常、响应结构异常和非 `200` 的未知业务错误都不重登、不重试，并保留现有的有限重试与错误返回。这遵守“403/429 立即停止”和“未经确认不猜测平台错误语义”的约束。重新登录失败时同样停止；每次执行最多一次登录恢复。

会话读取、写入、失效的所有错误均降级为安全失败或既有无状态登录路径，不暴露 token。Desktop 宿主拒绝错误账户绑定、超限请求、无效能力凭证和非预期方法/路径。

## 测试与验收

- Desktop：加密会话记录跨 `DesktopConfigStore` 重建可读取；账号/密码/开关改变会清除；`settings.json`、公开状态和诊断环境不包含 token。
- 宿主：仅接受受权的回环请求；验证 `Origin`、方法、路径、大小、账户指纹和停止生命周期。
- Python：首次导出登录并保存；后续导出复用；宿主缺失时兼容现有登录；401 恰好清除、登录一次并重放一次；403/429/未知业务错误均不重登；错误与进度不含 token。
- 回归：现有智汇单元/CLI/验收测试、Desktop config-store 测试、TypeScript typecheck、Python 测试、`git diff --check`。

## 不在本次范围

- 不猜测 token 的固定 TTL，也不按时间主动刷新；平台没有提供已确认的过期时间。
- 不增加“手动登出”界面；用户变更或清空智汇设置已能使缓存失效。
- 不把通用凭证保管改造成跨所有集成的平台；本次只抽出可复用的会话 provider 边界，避免无需求的通用化。
