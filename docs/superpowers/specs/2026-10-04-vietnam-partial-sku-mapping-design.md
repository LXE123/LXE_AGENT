# 越南备货 PR6：SKU 映射缺项留空

## 基线、目标与边界

本模块位于 Clean Stack 的新 PR6，分支 `codex/vietnam-clean-pr6-sparse`，基线为新 PR5 `124d43faa445375d1be7bf0185b04511a6fdbe37`。它依赖前序的受信 SKU current、Workbook 和在线 Workflow；不在 `main` 开发。

发布后运营仍只在 Desktop「工作台 → 模板与数据源 → 越南 SKU 参数表」上传一张 `.xlsx` 映射表，随后在聊天中运行现有无参数的越南备货命令。应用继续使用内置五表骨架和同一轮 VN8806 雅仓三类导出。PR6 使本轮雅仓 SKU 即使没有对应映射行，仍出现在最终五表中；已有映射行缺个别价格时，也能保留其他可计算结果。无第二个上传入口，无历史九表、相似 SKU、款号、商品名称或其他价格兜底。

本 PR 只调整映射表的内容校验、五表合并和公式、Office Kit 结果校验、相关测试与现行文档。Desktop 上传与回滚界面、受信版本存储和快照机制、四项长期参数、雅仓导出链路、聊天单次参数覆盖均不新增能力。

## 输入校验与运行顺序

当前受信映射表必须存在，第一张表仍须有 `SKU`、`成本`、`跨境价`、`折扣价`、`热销标记` 表头，并且至少有一个非空、唯一的 SKU。每行三项价格允许分别为空；一行价格全空、但 SKU 合法，也算有效映射行。非空价格必须是有限、非负、可精确写入 Excel 的数值；显式 `0` 是有效数值，绝不按空白处理。热销标记可空，非空时沿用现有 `1` 或 `2` 约束。可选 `上架时间` 保持现有格式校验，若填写则在生成时与仓库产品创建时间核对。重复或非法 SKU、缺表头、公式输入格、非法数值或精度、损坏及不安全的 XLSX 继续拒绝。

上传候选、暂存副本、受信 current/previous 和运行私有快照走同一内容校验；沿用现有文件大小、ZIP 条目及解压量、摘要、revision、回滚和并发保护。缺 current、空表、坏表或坏配置继续在调用雅仓前失败。上传时不调用雅仓，也不要求映射表预先覆盖未来的雅仓 SKU。

生成时先取得受信 current 的私有快照，再读取本轮三类雅仓数据。按雅仓动销与当前库存的 SKU 并集作为五表行集合，以精确 SKU 对运营映射表做左连接；映射表中不属于本轮的额外 SKU 不进入结果。雅仓动销、当前库存、仓库产品、权威在途、必需标题或创建时间缺失时，沿用现有错误，不把雅仓来源问题视为映射缺项。直接调用离线五表生成入口时，也须拒绝没有任何有效 SKU 的映射表。

## 每行输出与公式依赖

“缺映射行”与“已有行但字段为空”必须以 `SKU in parameters` 区分，不能用全空 `SkuParameters` 混同：

| 本轮 SKU 状态 | 主表直接映射值 | 备货结果 | 财务结果 |
| --- | --- | --- | --- |
| 映射表没有该 SKU 行 | `B` 热销、`G` 成本、`AE` 跨境价、`AJ` 折扣价均空 | `AC` 备货天数、`H` 最终备货量均空 | `AF:AM` 全空 |
| 有映射行，热销值为空 | `B=2`，已有价格照填 | `AC`、`H` 按现有规则计算 | 按各价格字段是否存在计算 |
| 有映射行，个别价格为空 | `B` 取显式值或默认 `2`；只有缺失的价格格为空 | `AC`、`H` 仍按热销、销量、库存和在途计算 | 只留空依赖缺失价格的列 |

三类雅仓来源表、本轮 SKU、标题、库存、销量、权威在途、上架时间，以及主表 `J:AB`、`AV:AY` 等不依赖映射的公式和结果继续保留。缺映射行时，绝不能让空 `B` 经原 `AC` 公式变成 `0` 天，再让 `H` 生成错误的补货量或负数。

财务列按骨架现有依赖逐列决定是否计算；不把整段财务列作为一个不可分割的结果：

| 结果列 | 必须存在的映射输入 | 其他条件 |
| --- | --- | --- |
| `AF`、`AI` | `AE` 跨境价 | 无 |
| `AG` | `AE` 跨境价、`G` 成本 | 无 |
| `AH` | `AE` 跨境价、`G` 成本 | 显式 `AE=0` 仍按现有零分母错误规则拒绝，不能误作缺值 |
| `AK` | `AJ` 折扣价 | 无 |
| `AL` | `AJ` 折扣价、`G` 成本 | 无 |
| `AM` | `AJ` 折扣价、`G` 成本 | 显式 `AJ=0` 仍按现有零分母错误规则拒绝，不能误作缺值 |

显式零保留在 `G`、`AE`、`AJ` 输入格中，且参与可计算的金额公式；它不会触发“缺失”分支。以显式零价格作分母的利润率仍按现有规则报告公式错误，避免把真实计算问题伪装为空映射。仅当依赖输入缺失时，`H`、`AC` 或对应财务列才使用包裹原骨架算式的条件公式，使 Office Kit 的缓存结果也为空；输入齐全的单元格保留原骨架公式。其他骨架公式保持原有业务逻辑和版式。结果校验必须以同一依赖规则推导每行应有的公式和缓存值，不能仅因缓存空白就放行缺公式、错误公式或额外错误。

## 重算、校验与交付

继续由项目固定的 Office Kit 重算临时工作簿，验证后才原子交付最终 XLSX。校验器核对恰好五张表、表头、雅仓 SKU 精确集合与投影、权威在途、上架时间、映射直写值和每行预期公式。对本应留空的 `H`、`AC`、财务列，公式仍须存在并符合条件版本，缓存只能是 `None` 或空字符串，不能是 `0`、空格或错误值；对本应可计算的结果，缓存须是有限数值。已有行且热销可用时，仍按现有算式核对 `H` 的补货量；缺映射行不做这个数值等式，却必须核对 `H`、`AC` 真正为空。

继续只容许骨架已知的 `AB` 在日均为零时产生 `#DIV/0!`；其他意外公式错误一律拒绝。不能把错误、旧缓存或 Office 重算失败解释为映射空值。映射表不完整是可生成的输入状态，不应把整轮当作失败；生成命令成功时 `sku_count` 仍是本轮雅仓 SKU 总数，只发送最终五表 XLSX。

## 验证与文档

使用合成映射表和合成雅仓来源覆盖：缺映射行、三项价格分别缺失、组合缺失、热销空默认 `2`、显式 `0`、完全匹配、映射额外 SKU；同时保留空 current/空表、重复 SKU、非法或超精度数值、不安全 XLSX、雅仓必要来源缺失的失败用例。至少一条混合 SKU 集成用例必须实际经过受信映射表安装或快照、Office Kit 重算与五表校验；对公式和缓存各做故意破坏的负例，证明空结果不能遮盖错误。可在业务环境只读核对运营本机映射表，但不得提交真实业务表或调用生产雅仓。

更新现行业务说明、映射表契约和 `vietnam-stock-recommendation` Skill：明确单表上传位置、未匹配 SKU 和空价格可继续生成、哪些结果留空，以及真正无 current/坏表/雅仓缺数据仍报错。历史 PR3/PR5 设计与交接记录保留其当时口径，以 PR6 文档和最终交接说明新规则。定向测试从仓库根运行；合并前的全量验证仍按仓库规范在最终同步 `main` 后进行一次。收口时记录分支、依赖、改动、入口、测试、限制和 Git 状态。提交、推送、建 PR、合并分别按仓库规范取得批准。

真实雅仓联调、Electron 原生界面和 Windows 安装包验收仍需对应环境；本地合成测试不能声称覆盖这些现场项目。
