# 店铺名称与国家标签

MSKU 仍通过马帮网页接口下载 XLSX；本次只修正店铺名称和认证错误提示，不切换赛狐，也不改变库存算法。

## 名称从哪里出错

网页的 `.texts` 或子站点链接中嵌套了 `.shop-country-cn`。原来的 `get_text()` 把国家一起取出，例如 `Amazon-YYH-US美国`；官方店铺列表却叫 `Amazon-YYH-US`。

解析时只移除该标签，保留店铺名称本身的中文。网页下载 ID 与类型保持原值，官方 Listing 继续使用 `sid`。

## 旧名称与历史文件

解析器在本次内存中记录同一节点清理前后的名字。官方查询先精确匹配；没有匹配时，才读取网页并尝试这个经过验证的旧别名。别名必须唯一，不能通过去掉“美国”等文字或模糊匹配来猜测。规范名称精确匹配成功时不会额外读取网页或 Cookie。

原有文件名函数只保留 ASCII 字符，因此 `Amazon-YYH-US` 与 `Amazon-YYH-US美国` 本来就使用同一个 `Amazon-YYH-US` 文件名前缀。这里保留既有文件规则，不重命名历史文件，也不扩大文件搜索范围。输入旧名称仍可沿用其现有文件链；新一轮从店铺解析开始，返回名称统一为干净名称。两套名称是同一店铺的别名，不能声称它们原来拥有隔离的文件目录。

## 认证判断

真实库存 CLI 的失败结果新增 `auth_refresh_required` 布尔值，由异常是否属于 `MabangAuthError` 决定。外层 CLI 优先使用该字段，避免在实际错误中的店铺 ID、响应数据等位置找到 `401/403` 就建议刷新 Cookie。错误文字仍原样保留；官方数据服务的鉴权失败也不会通过刷新浏览器 Cookie 修复。

仓库阶段最多刷新并重试一次，已成功的 Listing 和组合查询不重跑。其他尚未提供结构化标记的命令沿用原有提示逻辑，本次没有全局改写其认证行为。

## 验证方式

定向测试覆盖国家标签、中文店铺名称、欧洲子站点、重复节点、旧别名歧义、官方精确匹配优先、下载 ID 与 sid 区分，以及销量→库存→备货文件链。分别验证真正认证异常和仅包含 `401/403` 的业务错误。

真实业务文件与采集清单存入独立验证目录，不提交业务数据，也不覆盖正式数据集。

2026-09-07 的 YYH-US 实测：网页返回规范名 `Amazon-YYH-US`、旧别名 `Amazon-YYH-US美国`，下载 ID 仍为 `1039477`。新源表时间为 `202609070944`，2358 行；销量分析同为 2358 行。官方 Listing 完整读取 7296 条，查询 637 个去重组合 SKU，仓库查询展开为 2194 个 SKU。源表下载至真实库存生成共约 227 秒。

真实库存四个 Sheet 为组合 614 行、普通库存 1480 行、无本地 SKU 226 行、无库存数据 38 行，合计 2358；备货计算使用同轮销量与库存报告，处理 2094 行，默认模板 v1。未关联货件接口另外返回 `查询FBA店铺列表鉴权失败(status=401)`，所以没有加载旧快照，报表明确显示“本次未扣减未关联货件”。这份输出用于名称修复验收，不作为包含全部扣减的发货建议。

本机验证目录为 `outputs/mabang-store-country-fix-20260907/`，清单 `validation.json` 保存各阶段结果、原始错误和工作表行数。
