# MSKU 下载阶段核验 Active

单店、单站点继续下载马帮原始 XLSX，随后完整分页查询官方 `pStatus=["Active"]` Listing。原始行全部保留，追加“在售核验结果”“是否参与计算”“排除原因”。销量、深圳库存和备货计算使用同一个 Active 范围。

## 核验和文件契约

- 网页 ID 仍用于下载；官方 Listing 使用 `sid`。网页名称与 ID 必须唯一对应，多站点整组通过网页父子关系识别，并在查询 MSKU 记录、申请导出、创建输出目录之前拦截。CLI 返回 `context.reason=multi_site_group`、父级 `group` 和真实子站点 `candidates`，不刷新 Cookie、不自动选择或拆分站点。该规则取代此前允许整组下载原表的行为。
- 官方返回的平台状态必须为 `Active` 或已验证的中文“在售”；分页、店铺和站点均完整校验。查询失败不发布源表，也不刷新网页 Cookie。
- MSKU 与 ASIN 精确匹配，SKU 大小写保留。源表 ASIN 为空时要求唯一绑定；已匹配 MSKU 的 ASIN 不一致、绑定变化和类型冲突均报错。缺本地 SKU 的 Active 行保留原始空绑定。
- 未匹配完整 Active 集合的行标为“未确认在售”，不推断成“停售”。`Amazon.Found.*` 按相同规则处理。近期销量不改变排除规则。
- 隐藏的 `Active核验信息` Sheet 保存版本、店铺、站点、采集时间、完整 Active 绑定和源数据指纹。源表被改动或标记与快照不一致会被拒绝。
- 源表先在隔离临时目录完成下载、转换和核验，再原子发布。同一分钟的已有同名源表不会被覆盖。
- 销量和真实库存报表各保存同轮核验信息，最终计算检查两者完全一致。历史无核验文件需重新下载并生成报表，不自动回退全量。
- 库存仅复用本轮文件的 Listing 绑定，实时查询组合明细和深圳库存。没有 Active 行时返回“无符合条件的记录”，不查询仓库或生成建议。
- 四个命令保留已有参数和返回字段，新增 `original_row_count`、`active_row_count`、`excluded_row_count`。这些字段描述源表范围；最终建议数量还受缺库存等原有条件限制。
