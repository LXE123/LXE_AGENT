# 马帮巴西海外仓导出：实现与验收

## 使用与范围

独立 Skill `mabang-brazil-export`，命令 `lxeskill mabang brazil-overseas export run --params '<JSON>'`。`reports` 选择库存动销、三个月内待签收、三个月前已签收，可以组合。复用 main 的马帮 ERP 配置和已有登录态，不自动登录／刷新，不增加桌面设置，不涉及马帮 TMS 或 Amazon 备货计算。东南亚数据准备入口仅在用户明确选择时调用巴西导出；巴西不属于东南亚。

协议参考 PR #65（`49df456ffc3cbb90a331ba1a6af504378a15e1d5`），保留仓库映射、18 列调拨模板与原始格式，修正仅导出第一页的问题。调拨查询每页 20 张，逐页导出并核对 ID 对应的批次编号；不把文件行数当单据数。整任务最多 1000 个调拨查询页、15 分钟，文件发送失败不重跑导出。

库存查询和导出使用服务端筛选状态。巴西与已有 Amazon 库存路径共用按账号摘要的跨进程锁，覆盖筛选至下载；下载后仍校验仓库。未参与本应用锁的网页操作仍可能影响服务端筛选，因此保留总数及文件核对，不宣称锁能约束平台网页。

## 真实接口验收（2026-09-23）

使用桌面现有马帮账号的已有认证，不执行登录或刷新。首先查询三类真实列表并检查网页实际分页协议，再进行导出。

| 报表 | 查询总量 | 校验后明细行数 | 列数 | 结果 |
|---|---:|---:|---:|---|
| 库存动销 | 2334 条库存记录 | 2334 | 35 | 原始 XLSX 已保存 |
| 三个月内待签收 | 7 张单据 | 1847 | 18 | 原始 XLS 已保存 |
| 三个月前已签收 | 15 张单据 | 3206 | 18 | 原始 XLS 已保存 |

库存首轮查询 `pageHtml=false`，网页实际调用 `warehouse.getSearchWarehouseStockPage`，参数为 `page`、`rowsPerPage`。生产响应给出 2334 条、47 页、每页 50 条；下载后再次核对总数，文件仓库及首批 SKU 样本匹配。库存 35 列包括原生 `销量(7)`、`销量(28)`、`销量(42)`、仓位库存、可用库存量、最后出库／入库时间。

调拨 `pageHtml` 明确提供总数、区间、当前页与总页数。`input[name="allot[]"]` 的 `value` 对应单据 ID，`data-code` 对应文件批次编号。本轮两类都只有一页；实际原表覆盖全部 7／15 个批次。真实业务内容不提交，仓库中只保存替换过 ID／批次号的最小协议 fixture 和合成 Excel 测试数据。

初次严格解析两类 XLS 都遇到 `CompDocError: Workbook corruption: seen[2] == 4`，停止并保留库存成功文件，异常原件不交付。离线定位为平台旧 XLS 的 OLE Root Entry 声明 512 字节短流，但 FAT 尾链继续指向 Workbook，导致 xlrd 误将后续工作簿扇区标记为短流。兼容处理仅接受这一已证实结构：验证长度、扇区边界、无循环、目录／分配表不重叠、元信息短流及 Workbook 结束标记，再解析原 Workbook 字节。不启用 `ignore_workbook_corruption`，其他结构异常继续失败。结果保留兼容读取说明。

调拨存在批次、仓库、日期等纵向合并单元格。仅在校验视图中按真实合并范围展开值，原文件字节不变。修正后重新验收两类调拨成功；已通过的库存未重复导出。

真实生成的文件保存在主工作区 `var/artifacts/mabang/brazil/exports/` 下，按账号摘要与运行目录隔离。未提交业务原件、账号、Cookie、Token 或下载签名。

## 模拟与契约验证

- 巴西定向 43 项通过：分页／总数变化、重复 ID、提前空页、零记录、预算、账号锁及跨进程互斥、原始字节、合并单元格、真实 BIFF/OLE 合成文件、尾链兼容与循环拒绝、部分失败附件。
- 客户端覆盖认证只读、401／403／429、不合法下载域名、重定向拒绝、非 JSON、只读查询有限重试、提交／下载不重试、脱敏后截断。
- Python 定向执行巴西、Amazon 库存、`tests/lxeskill` 与 `tests/infra`。首次沙箱端口限制导致本机 HTTP fixture 失败，沙箱外复验；新增 Skill 与命令导致的清单计数断言已同步并定向通过。
- Bun 命令及 Skill 加载测试 21 项通过，doctor 与 diff 检查通过。最终 rebase 后 `bun run verify` 的协议、生产边界、TypeScript 检查和 Bun 全量通过：1792 项通过、5 项跳过。Python 全量首次发现新增附件测试未恢复全局工作区，修正测试清理后针对巴西及 WMS 的 63 项通过，并单独复验 Python 全量：2006 项通过、2 项跳过、54 个子测试通过。30 条 warning 为已有 aiohttp 弃用提示；未重复跑已通过的 Bun。

## 验收边界

真实数据不足 20 张单据，多页、零记录和失败分支由模拟覆盖；不将其写成已完成真实多页验证。库存完整性证据为查询总数、实际仓库和首批 SKU 样本，未遍历所有 47 页逐 SKU 比对。新 Skill 的普通桌面对话提问、取消、附件发送与跨流程调用仍需用户侧对话验收；CLI 部分成功附件契约已有自动化测试。
