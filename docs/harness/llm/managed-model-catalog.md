# 云端模型描述 v3

公司模型由本地供应商适配器和云端发布描述共同解析，模型 ID 不再必须存在于本地目录。个人模型继续读取本地目录。供应商、协议和地址固定，不接受下发脚本、任意请求字段或新供应商。

Desktop 每分钟主动同步，优先 v3，缺少 v3 才回退 v2／旧状态。加密缓存同时保存目录、配置版本和凭据集合；只在新增目标或凭据版本变化时领取 Key（请求带 model_schema=3）。收到明确下架、不可用或不支持的配置后先移除旧凭据，再逐项获取新凭据。断网保留缓存，单项失败不会清除其他模型。

Desktop → Gateway → Agent CLI 通过现有结构化 IPC 传递整个状态。每次更新产生新的运行时快照，已取得快照的 turn 保持原模型和 Key，后续 turn 使用新快照。未知或失效目标可以显示诊断，但不能执行本地默认模型或个人 Key 作为替代。

`managed-model-definition.ts` 是可供浏览器加载的严格契约。`compat` 的缺省值是项目现有行为，不自动跟随 PI。仅支持已实现的三个协议子集，完整参考和许可见 `pi-compat-reference.txt`。普通请求和总结共用协议参数构造。

迁移测试覆盖全部现有模型的请求形状；集成测试使用本地目录不存在的模型验证同步、选择、重启和撤回。参数变化不重新领取 Key；模型名、Key 和参数版本分别处理。管理员仅修改默认项时保留用户仍在发布列表中的当前选择。

上线顺序是兼容云端 → Agent 升级 → 发布新模型／新参数。旧 Agent 无法理解的目标由云端拒绝发放旧协议凭据。本次不包含真实供应商试调用。
