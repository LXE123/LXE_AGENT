# 越南备货 PR3：内置五表骨架与离线生成

## 范围

PR3 提供一个不调用雅仓生产接口的 Python 入口：给定同一轮 PR2 `VietnamSources`、运营上传的 SKU 映射表和输出路径，生成五表 XLSX，调用项目固定的 LibreOffice Kit 重算，校验通过后才交付文件。雅仓导出、聊天 Skill、Desktop 上传入口和发送文件分别留在后续 PR。输出路径已存在时拒绝覆盖。

最终文件只含 `越南备货清单`、`雅仓库存`、`雅仓动销`、`数据更改`、`库存商品信息`，且只含本轮 VN8806 动销和库存列表的 SKU 并集。

## 输入口径

- 每个本轮 SKU 必须同时出现在动销、当前库存和仓库产品资料。当前库存的 `在途数量` 是总在途唯一来源；动销的 `在途` 只做差异诊断，不能补空值。
- 仓库产品资料的 `创建时间` 经业务确认就是真实上架时间。按精确 SKU 关联，规范为 `YYYY-MM-DD HH:MM` 文本写入 `库存商品信息!K`；主表 `AA` 继续使用模板对该列的查找公式。不能写 Excel 日期序列，因为新品公式使用 `DATEVALUE(LEFT(AA,10))`。缺商品或时间即失败。
- 运营映射表按精确 SKU 提供 `成本`、`跨境价`、`折扣价`，三项都必须有显式值。显式零保留。热销标记有显式值时使用，否则采用已确认默认值 `2`。缺失、重复、非法值直接报告；不使用模板历史值、相似 SKU 或产品名称推断。
- 映射表可保留旧版可选 `上架时间` 列以便读取旧文件，但 PR3 不用它计算；若非空且与仓库产品时间冲突则失败。新运营表不要求填写该列。
- `品牌`、`链接`、`产品图片`、`传过的店铺` 缺少已确认来源，主表留空。仓库产品资料保留雅仓原始图片链接，不继承历史图片、批注或超链接。

## 内置骨架

发布后不能依赖用户曾绑定过完整模板。PR3 从全新工作簿构造无历史业务数据的五表骨架，仅移植真实模板已审计的表头、列宽、样式和计算公式，并把它作为 Python 包内资源随版本发布。不得提交或打包用户提供的九表原件，也不得留下历史 SKU、成本、价格、图片、批注、超链接、外链或可恢复的共享字符串。

主表逐列填值和公式，不能复制历史整行。`H` 和 `J:AC` 的备货公式结构在真实模板 8,300 行一致；`AC` 为单格数组公式，须逐行重建引用。`AV:AY` 始终固定引用 `数据更改!A2:D2`，不能相对平移。`AE`、`AJ` 由映射表输入，价格利润公式只取已审计且适用于完整价格输入的列。`AN` 直接写权威在途，`AO:AU` 保持空白。四项运行参数默认 `0.8 / 0.8 / 0 / 3900`，由本次调用显式覆盖；Desktop 设置优先级由后续 PR 接线。

## 重算与校验

使用已有 `shared.office` 入口和宿主配置的 `LXE_OFFICE_NODE`、`LXE_OFFICE_CLI`，不寻找系统 LibreOffice，也不另写公式引擎。生成和 Kit 重算都在临时路径完成。Kit 失败时保留实际且经必要脱敏、截断的诊断；任何失败都不能留下看似成功的成品。

重算后分别读取公式与缓存值，核对恰好五表、表头及列序、本轮 SKU 精确集合、来源表投影、上架时间、权威在途、必需公式和关键备货结果。关键结果必须是有限数值，允许模板公式本身产生有业务意义的负备货量。真实模板已有 `AB` 在日均为零时的 `#DIV/0!`；仅在该已知条件下容许这一非最终结果错误，不能把旧缓存当作全量 Golden。其余关键计算错误失败。

验收需覆盖合成来源的新 SKU、缺失字段、显式零、时间与新品边界、价格精度、公式行扩展、Office Kit 的真实重算、目标文件原子交付，以及 Python wheel 中骨架资源的存在与敏感内容扫描。真实九表模板只在本机作为只读公式和样式参考，不进入仓库或安装包。
