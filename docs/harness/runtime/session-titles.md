# 会话标题

行为参考 dsh 默认的 first-prompt 标题服务。新会话第一条有效用户文字先产生临时标题，首个主模型请求开始时再后台生成一次正式标题。后续对话不更新标题，升级前的会话不自动补生成。

菜单、双击侧边栏标题、`Cmd/Ctrl + Alt + G` 打开同一个改名弹窗。手动保存固定标题，即使后台模型忽略取消并迟到返回，也不能覆盖它。空白会话不可改名，重复名称及相同名称可以保存。

## 数据与并发

会话状态仍属于 Bun。`SessionTitleService` 协调生成、改名、取消和显式 `refresh()`；后者没有 UI 入口。`SqliteRuntimeStore` 用现有每会话写队列追加标题事件，然后更新查询投影：

- `session_title`：接纳的标题、来源、递增版本和来源消息 ID；第一条临时标题同时保留原始用户文字。
- 第一条有效用户消息的事件同时保存 `title_input` 元数据，保留原始文字及消息 ID。即使进程在写入标题前中断，也不会把下一条消息误当作首次输入；手动标题先于有效文字时也可以显式刷新。
- `session_title_request`：辅助请求的系统提示、JSON 输入、模型身份及生成控制。输入超限时带明确拒绝原因，不调用模型。

这些事件不进入消息展示、历史消息计数或模型上下文。原始 transcript 不迁移。SQLite 的标题字段是投影，启动时通过现有增量索引恢复追加成功而投影尚未更新的事件。旧记录的标题来源留空，不推断为手动标题。

标题生成复用该回合的 Provider 和凭据快照，三个协议的输出预算和推理强度均只对这次辅助请求生效。独立取消信号不随正常回合结束而取消；删除会话及关闭 Runtime 时取消。自动提交必须满足标题版本未变、会话仍存在、信号未取消；手动改名先取消旧任务再串行写入。

`sessions.rename({session_id, title})` 返回已接纳的会话元数据，包括 `title_version` 和 `title_source`。Renderer 保留每个会话的最高标题版本，投影到列表、搜索和详情，防止旧请求回滚新名称；标题刷新不移动阅读窗口。

## 生成规则

- 临时标题：5 个空白分隔词、40 UTF-8 字节；正式及手动标题：80 UTF-8 字节。
- 标题目标：约 5 个非 CJK 词或 10 个 CJK 字符，使用用户语言。
- 完整 JSON 消息输入：4096 UTF-8 字节；超限拒绝，不截断。系统提示不计入此输入限额，与 dsh 一致。
- 输出预算：4096 token（不超过模型能力），采用最低支持的推理强度；整体调用超时 60 秒。
- 只读取用户原始文字；纯附件、系统注入、心跳、助手和工具内容不作为标题来源。
- 去除终端控制序列、不可见方向字符，合并空白；按 Unicode 码点截取到字节预算。
- 模型输出取第一条非空行并去掉整行星号强调。工具调用、长度上限、空输出、超时和请求异常保留原标题并记录实际错误，不自动重试。
- 辅助调用的内容与用量不计入主回复、上下文占用和回答页脚。

## 验证

定向测试包含 `session-title.test.ts`、`session-title-controls.test.ts`、Renderer 的 `session-titles` 组，以及协议和 Dashboard 服务用例。Electron 组使用生产 UI 与内存 RPC fixture，覆盖三个入口、IME、失败重试、重复提交、刷新、搜索及浅色／深色窄窗口。`LXE_SESSION_TITLE_SCREENSHOT` 可保存布局截图。
