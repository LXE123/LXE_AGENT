# Context Pruning and Compaction

本篇维护工具输出裁剪、请求预算和上下文压缩机制。压缩缩短模型看到的历史，原始消息仍保存在 transcript 中；持久化和图片规则见 [Context Persistence](context_persistence.md)。

实现以 [`context.ts`](../../../../packages/agent/runtime/src/engine/context.ts) 和 [`context-meter.ts`](../../../../packages/agent/runtime/src/engine/context-meter.ts) 为准，摘要提示词也在代码中维护，不在文档复制一份。

## 默认预算

| 项目 | 默认值 |
| --- | ---: |
| 模型窗口缺省值 | 256000 token |
| 输出预留 | 20000 token |
| 请求前压缩软阈值 | 模型窗口的 90% |
| 最近原始消息保留目标 | 20000 token |
| 单步工具结果文本预算 | 10000 token |
| 单张图片估值 | 1600 token |
| 每次摘要调用的重试上限 | 3 次重试，即最多 4 次尝试 |

实际窗口来自所选模型 descriptor。硬上限为窗口减去输出预留；请求前触发线取软阈值与硬上限中较小值，并扣除待追加的环境上下文。最近消息保留量是按完整消息边界选择的目标，不保证精确等于该数字。

## 工具结果裁剪

执行循环收集一批新工具结果后，在追加消息前进行 block-aware 裁剪。文本超限时保留首尾并插入裁剪说明；多个 text block 共享预算。图片保留，另计图片估值；工具调用 ID 和错误标记保持不变。

裁剪针对新结果，不在每轮开始时重写旧记录。长期历史长度由摘要压缩处理。

## 完整请求估算

本地估算包含 system prompt、统一消息、可见工具 schemas 和图片。文本近似按 UTF-8 字节数除以 4 向上取整；结构先序列化，图片按独立估值计算。

若历史中存在与当前模型和请求配置指纹匹配的 usage 锚点，使用：

```text
已知实际输入 token + 当前本地估算 - 锚点处本地估算
```

无匹配锚点时使用纯估算。请求内省略图片等导致 usage 不再代表共享历史的情况，不用于校准共享历史。校准能减少估算偏差，不能保证供应商一定接受请求。

## 历史与长 turn 压缩

优先围绕最近的原始对话保留完整消息，将较早历史交给模型总结。已有摘要会作为更新摘要的输入；结果使用 `compactionSummary` 保存摘要、压缩前 token 数和文件读写线索，再接保留的原始消息。发送给 Provider 时才投影为用户上下文。

当前 turn 太长，或没有可单独总结的旧 turn 时，可按 assistant 步骤切分：保留最近步骤，把该轮用户输入及前半段执行过程交给摘要模型。必要时分别总结先前历史与当前 turn 前缀，再组合为一个 checkpoint。工具调用和结果在边界处保持闭合。

因此，当前用户输入不保证始终逐字保留在模型视图中；完整原文仍保存在 transcript。摘要提示词要求保留目标、约束、进度、决策和后续工作，但最终摘要质量需要人工判断，审查方式见 [PR 审查规范](../../../pr-review.md)。

文件读写清单由代码从工具记录提取、合并并写入摘要附属信息。图片、思考签名和不透明数据在摘要输入中采用占位，不发送完整二进制或 opaque 数据。

## 摘要调用与失败

摘要使用本轮 Provider，禁用工具和 thinking，usage 计入本轮。空结果及明确可重试的 Provider 错误按上表重试，退避从 2 秒开始递增；普通未知异常、明确不可重试错误或摘要本身超出上下文不反复尝试。取消立即中止。

只有摘要有效、归一化后 token 确实减少且未取消，才追加 compaction patch。写入后再次检查硬上限；压缩变短但仍超限也会结束本轮，不能把“成功写入摘要”当作“一定可以继续请求”。

没有安全前缀、摘要失败或 token 未降低时返回具体原因，不写 compaction patch。执行循环据此报错；原有 transcript 不被覆盖。

## Overflow 与收尾维护

供应商明确报上下文溢出时，Runtime 强制尝试压缩，不要求本地估算先超过软阈值。压缩成功且回到硬上限内，才在同一 step 重试一次；再次溢出或压缩失败则结束，不消耗普通网络错误的重试预算。

Final 交付后也可以检查长期预算并追加摘要。该阶段异常或仍超限只记录 warning，不撤销已交付答案。下一轮根据已保存的模型视图继续处理。
