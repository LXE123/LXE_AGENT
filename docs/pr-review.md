# PR 审查规范（LXE_AGENT ）

## 1. 协作流程

所有进入共享 `main` 分支的仓库改动，包括代码、文档和配置，统一通过 PR 合并。

### 1.1 开发与提交

开发和提交在任务分支进行，再创建目标为 `main` 的 PR。工作区选择与操作见 [AGENTS.md](../AGENTS.md)。

一个 PR 尽可能聚焦一个问题，让未参与开发的人也能理解和评审。说明改动缘由、内容和预期影响，保留必要的决策与限制。

PR 标题与 commit 说明使用英语，commit 类型前缀遵循 [AGENTS.md](../AGENTS.md#commit-规范)。

每次更新 PR 后，补充一条简洁、可独立理解的 comment，说明本次改动和验证情况。

### 1.2 审查

PR 由 AI 与维护者共同审查。

审查时说明发现的问题、实际验证结果和未确认事项。

已有审核结论可用于其覆盖的改动；后续发生实质变化时，应重新审核受影响部分。重要的架构或行为改动，建议由另一位维护者复核。

### 1.3 合并与同步

合并前，确认验证适用于当前代码和最新 `main`，处理审查中需要修复的问题；第 2 至 5 节列出的重点变更须经维护者确认。通过后，由有合并权限的维护者按仓库规则合并 PR。

AI 代为合并时须已有明确授权。确认远端 PR 已合并后，再同步本地 `main`。验证范围、分支更新和 worktree 归还按 [AGENTS.md](../AGENTS.md) 执行。

## 2. 共同审查重点

检查实现逻辑、接口、数据读写、错误处理及相关验证，同时判断改动的必要性、设计取舍，以及对使用体验或业务结果的影响。

核对模块调用边界：Electron 与 agentcli 通过 JSON-RPC 2.0 通信；Electron 通过 lxeskillCLI 暴露的命令调用业务能力。

重点关注以下变更：

- 改变模块职责或数据归属。
- 引入新的跨模块依赖。
- 改变模块之间的公开接口契约。
- 修改用户交互入口的处理方式，例如将对话输入按关键词分流到预设工作流。
- 新增或修改 Skill 说明、面向模型的命令描述或使用指引。具体要求见 [Skill 编写与审查要求](#21-skill-编写与审查要求)。

判断依据见 [架构简介](architecture/README.md)。

修改文档时检查相关链接与过时引用。

### 2.1 Skill 编写与审查要求

Skill 按主要用途分为**指导 Skill**和**业务流程 Skill**。

**1. 指导 Skill**

说明某类事情应该怎么做，提供适用场景、操作方法、工具用法和必要注意事项，供不同任务复用。

**2. 业务流程 Skill**

围绕具体业务任务，重点讲清两件事：

- **数据源是什么**：需要哪些数据或资料，从哪里获取。
- **产出什么**：使用这些数据完成什么业务目标，交付什么结果。

**3. 共同要求**

- 讲清正确用法和必要上下文即可，避免针对个别误判不断追加禁止事项。
- Skill 可以根据任务需要介绍 Electron、lxeskillCLI 等模块的内部结构、实现细节、数据组织和操作方法。

## 3. Electron 审查重点

- 新增或改变用户操作流程。
- 修改设备权限或应用授权规则。
- 修改安装、更新和升级策略。

模块说明见 [Electron 模块介绍](architecture/electron.md)；发布、安装和升级的验证入口见 [打包手册](desktop/packaging-pipeline.md)。

## 4. agentcli 审查重点

- 增加、修改或删除任何内置 Tool。
- 修改系统提示词、上下文来源、内容选择或组装规则。
- 修改上下文压缩机制、提示词或策略。
- 修改影响模型推进任务的策略，例如自动继续执行、追加引导消息或结束任务的规则。
- 修改模型调用配置，例如推理模式、采样参数或输出长度限制的默认值。
- 修改权限模式、写入范围或单次提权规则。

模块说明见 [agentcli 模块介绍](architecture/agentcli.md)。

## 5. lxeskillCLI 审查重点

- 修改业务规则、计算公式或计算口径。
- 新增或改变业务命令提供的能力及操作范围。

修改命令时，检查命令定义与实际行为是否一致，并同步受影响的帮助、命令手册和配套 Skill。维护方式见 [lxeskill 命令手册](lxeskill-cli/commands.md#维护这份手册)。

模块说明见 [lxeskillCLI 模块介绍](architecture/lxeskill-cli.md)。
