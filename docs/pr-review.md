# PR 审查规范（LXE_AGENT ）

## 1. 协作流程与审查分工

所有进入共享 `main` 分支的仓库改动，包括代码、文档和配置，统一通过 PR 合并。这一规则适用于所有维护者及其 AI 代理；不得直接向 `main` 提交或推送任务改动，也不得以本地合并任务分支后推送的方式绕过 PR。

### 1.1 开发与提交

开发和提交在任务分支进行，再创建目标为 `main` 的 PR。AI 可根据改动范围和并行冲突风险，复用属于当前任务的工作区或领取独立 worktree。工作区选择不改变审查要求，具体操作见仓库的 [AGENTS.md](../AGENTS.md)。

一个 PR 尽可能聚焦一个问题，让未参与开发的人也能理解和评审。描述具体问题、改动后的行为及必要的影响范围，列出实际验证结果和未覆盖的平台或场景。保留影响维护的决策与限制，省去临时讨论、重复文件清单和已放弃方案。

PR 标题与 commit 说明使用英语，commit 类型前缀遵循 [AGENTS.md](../AGENTS.md#commit-规范)。

每次更新 PR 后，补充一条简洁、可独立理解的 comment，说明本次改动和验证情况。

### 1.2 AI 技术检查

所有 PR 均先由 AI 进行技术检查，包括实现逻辑、接口、数据读写、错误处理，以及与改动相关的验证。

技术检查应核对模块调用边界：Electron 与 agentcli 通过 JSON-RPC 2.0 通信；Electron 通过 lxeskillCLI 暴露的命令调用业务能力。

修改 lxeskillCLI 命令时，检查命令定义与实际行为是否一致，并同步受影响的帮助、命令手册和配套 Skill。帮助与手册共用命令定义，维护方式见 [lxeskill 命令手册](lxeskill-cli/commands.md#维护这份手册)。

修改文档时检查相关链接与过时引用；发布、安装和升级的验证入口见 [打包手册](desktop/packaging-pipeline.md)。

AI 应说明发现的问题、实际验证结果和未确认事项。

### 1.3 人工审核

人工重点判断修改的必要性、设计取舍，以及预期行为或业务结果的变化是否可以接受。

涉及第 2 至 5 节所列的人工审核项时，AI 简单总结以下内容，提交人工审核：

- **修改缘由**：为什么要改。
- **改动内容**：具体改了什么。
- **预期影响**：可能影响哪些行为、使用方式或业务结果。

“预期影响”属于分析判断，不代表效果已经得到验证。

是否需要人工审核按改动内容判断，不因文件少、修改简单或提交者身份而免除。

已有审核结论可用于其覆盖的改动；后续发生实质变化时，应重新审核受影响部分。重要的架构或行为改动，建议由另一位维护者复核。

### 1.4 合并与同步

合并前，应基于最新 `main` 完成必要验证，处理技术检查中确认需要修复的问题；涉及人工审核项的，还须经人工审核通过。普通改动完成技术检查和必要验证后，可由有合并权限的维护者按仓库规则合并 PR。

AI 代为合并时须已有明确授权。确认远端 PR 已合并后，再同步本地 `main`。验证范围、分支更新和 worktree 归还按 [AGENTS.md](../AGENTS.md) 执行。

## 2. 各模块共同的人工审核项

以下改动需要人工审核：

- 改变模块职责或数据归属。
- 引入新的跨模块依赖。
- 改变模块之间的公开接口契约。
- 修改用户交互入口的处理方式，例如将对话输入按关键词分流到预设工作流，需要人工审核。
- 新增或修改 Skill 说明、面向模型的命令描述或使用指引。通用 Skill 和业务 Skill 均适用。

判断依据见 [架构简介](architecture/README.md)。

### 2.1 Skill 提供的工作上下文

Skill 为 Agent 提供任务知识、工作上下文和命令使用指引，具体操作由调用的工具或程序执行。例如，lxeskillCLI 的配套 Skill 介绍业务任务的做法，lxeskillCLI 通过 `lxeskill` 命令执行对应的业务操作。

Skill 也可以根据任务需要，向模型介绍 lxeskillCLI、Electron 等模块的内部结构、实现细节、数据组织和操作方法，帮助模型理解环境并使用工具完成任务。

这些说明属于提供给模型的工作上下文，本身不构成程序模块之间的耦合。模型根据上下文自主使用通用 Tool，不改变各模块的职责和数据归属。

审查时应区分：

- **Skill 提供的说明**：审查说明是否准确、是否有助于任务，以及操作是否符合任务要求。实现变化后，需要同步更新相关 Skill。
- **程序模块之间的依赖**：审查程序代码是否直接依赖其他模块的内部实现或存储结构，是否符合约定的接口边界。

例如，让模型了解 Electron 的日志目录来排查问题，或了解 lxeskillCLI 的参数文件来解释当前配置，都可以是合理的工作上下文。

## 3. Electron 的人工审核项

- 新增或改变用户操作流程。
- 修改设备权限或应用授权规则。
- 修改安装、更新和升级策略。

模块说明见 [Electron 模块介绍](architecture/electron.md)。

## 4. agentcli 的人工审核项

- 增加、修改或删除任何内置 Tool。
- 修改系统提示词、上下文来源、内容选择或组装规则。
- 修改上下文压缩机制、提示词或策略。
- 修改影响模型推进任务的策略，例如自动继续执行、追加引导消息或结束任务的规则。
- 修改模型调用配置，例如推理模式、采样参数或输出长度限制的默认值。
- 修改权限模式、写入范围或单次提权规则。

模块说明见 [agentcli 模块介绍](architecture/agentcli.md)。

## 5. lxeskillCLI 的人工审核项

- 修改业务规则、计算公式或计算口径。
- 新增或改变业务命令提供的能力及操作范围。

配套 Skill、命令描述与使用指引的人工审核按 [第 2 节共同要求](#2-各模块共同的人工审核项)执行；模块职责与业务分类见 [lxeskillCLI 模块介绍](architecture/lxeskill-cli.md)。
