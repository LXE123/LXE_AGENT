# agentcli 模块介绍

总览：[架构简介](README.md) · 审查入口：[PR 审查规范（LXE_AGENT ）](../pr-review.md)

agentcli 为模型提供工具、上下文和执行环境，由模型根据任务目标与执行反馈，自主决定调用哪些工具、使用什么参数，以及如何推进任务。

agentcli 由 `apps/agent-cli` 宿主和 `packages/agent/runtime` 执行核心组成，可以按职责划分为以下部分。

## 1. Agent Runtime

负责一次 turn（执行回合）内部的执行循环：

准备上下文 → 调用模型 → 执行工具 → 收集结果 → 继续执行或结束。

一次 turn 可以多次准备上下文、调用模型和执行工具，并按需进行上下文压缩。一个用户任务可以跨多个 turn 完成。

Runtime 同时处理执行过程中的失败、取消和终止条件。

## 2. Tool 模块

负责工具的注册、发现、调用和结果处理。

内置工具包括：

- `exec`：执行命令。
- `wait`：等待正在执行的命令，读取新增输出，也可终止进程。
- `ls`：列出目录内容。
- `find`：按名称或路径模式查找文件、目录。
- `grep`：搜索文件内容。
- `read`：读取文件。
- `write`：创建或覆盖文件。
- `edit`：修改已有文件的指定内容。
- `send_files`：发起文件交付事件，携带本地文件路径，由接入方决定具体交付方式。
- `ask_user_question`：向用户提出结构化问题并等待回答，仅用于桌面会话。
- `tool_search`：搜索可用工具，使匹配的延迟工具在后续步骤中可用。

此外，还支持通过 MCP 接入外部工具。

## 3. 会话与上下文管理模块

- **会话管理**：保存会话状态、消息历史和执行记录，支持历史恢复。
- **上下文管理**：组装模型请求所需的提示与历史，管理上下文预算、裁剪和压缩。

消息、工具调用及结果等记录保存在各会话的 JSONL 文件中；SQLite 管理会话元数据、索引和统计等数据。

### Skill 发现与加载

- 发现项目内置、用户添加及共享目录中的 `SKILL.md`，向模型提供可用 Skill 的名称、说明和文件位置。
- 模型根据任务需要，通过 `read` 加载 Skill 说明。
- 用户输入 `/Skill名` 时，按显式调用语法加载相应 Skill 指令。

Skill 提供任务说明与使用指引，具体工具调用由模型在 Agent turn 中决定。

agentcli 随应用提供前端设计、Office 文件处理、Skill 创建等通用默认 Skill，作为模型可按需加载的配套资源。

Office Skill 指导模型通过 `exec` 直接调用 Kit CLI，并按任务使用文档库检查结果；不经过 lxeskillCLI 的业务入口。

这里的 Skill 目录索引用于组织 Skill 说明文件，与 [lxeskillCLI 的命令 Catalog](lxeskill-cli.md#1-cli-入口与命令契约模块) 分别维护。

## 4. 供应商对接模块

负责内部统一格式与模型供应商 API 之间的双向适配：

- 将内部消息、工具定义和模型参数转换为供应商请求。
- 将供应商返回的流式响应（包括 SSE）转换为内部消息和事件。
- 处理模型能力差异、供应商返回的用量信息、错误和请求取消。

## 5. 权限管理模块

权限管理根据当前会话的权限模式，控制 `exec`、`write`、`edit` 的本地文件写入范围，并处理单次操作的提权审批。

**三种权限模式**

| 模式 | 本地文件写入范围 |
| --- | --- |
| 只读（`read-only`） | 受控工具不能修改普通文件，包括临时文件。 |
| 工作区写入（`workspace-write`） | 允许写入当前会话的固定工作区及指定临时目录。改变命令的工作目录不会扩大写入范围。 |
| 完全权限（`danger-full-access`） | 不施加 agentcli 的本地文件写入限制，仍受操作系统权限和工具自身校验约束。 |

**限制如何落实**

- `exec`：根据当前权限模式，为命令进程配置操作系统级的文件写入限制（通过执行沙箱实现）。
- `write`、`edit`：由工具实现检查目标路径、写入权限及文件是否发生变化。
- 完全权限模式仍经过正常的工具调用与策略处理流程，只是不施加上述文件写入范围限制。

**实际限制范围**

这三种模式主要控制本地文件写入，不能直接等同于所有业务操作的“只读”或“可写”。

例如，不写入本地文件的网络请求仍可能修改远端数据；MCP 工具也不会因为会话处于只读模式，就自动变成只读工具。外部系统的业务操作权限需要由相应工具或服务另行控制。

**单次提权审批**

桌面会话中的 `exec`、`write`、`edit` 可以为某次操作申请更宽的权限：

- 调用时显式提供 `sandbox_permissions` 和 `justification`，说明所需权限及原因。
- 申请满足当前操作所需的最小权限，由用户决定是否批准。
- 批准仅对本次工具调用生效，不改变会话的默认权限模式，也不授权后续调用。
- 审批被拒绝或操作失败后，不自动提权重试。
- 未提供审批通道的运行环境不能使用单次提权。

## 6. 对外协议与宿主管理模块

负责 agentcli 与外部调用方之间的接口，以及内部组件的生命周期：

- 定义 JSON-RPC 2.0 请求、响应和通知。
- 提供任务执行、取消及状态查询等接口。
- 装配内部组件，管理初始化、启动和关闭。

## 7. 统计与用量同步模块

负责记录执行过程中的调用与用量，并同步统计数据：

- 记录模型用量和 Tool 调用情况。
- 观察 `read`、`exec` 调用，记录 Skill 读取调用次数和关联业务命令调用次数；调用计数不代表业务成功次数。
- 通过公开 CLI 接口查询 lxeskill 命令与 Skill 的归属。
- 保存本地统计记录，并向统计服务器同步。

统计模块不参与工具授权和业务执行决策，统计失败不应阻断正常任务。
